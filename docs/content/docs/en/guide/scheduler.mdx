Configuration controls how a task behaves; Scheduler controls whether and when it participates in the selected profile's automation. Starting or stopping a scheduler is a separate runtime action.

## Task List

The current UI uses one list. Enabled tasks come first and disabled tasks follow a divider. Default sorting uses ascending priority; time sorting uses ascending next-run time, within those groups. Equal sort values retain their existing order. The sort preference is remembered.

Search matches the task's displayed name, backend event name and function identifier. The enabled/total counter describes the full profile, not just the visible search results. Clearing search restores the full list.

| Control                  | Result                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| Row switch               | Enable or disable that task immediately                                                  |
| Row date/time            | Set that task's next run time; the UI uses local display time and persists epoch seconds |
| Row gear                 | Open the task's detailed scheduling dialog                                               |
| Bulk enable/disable      | Enable all tasks, or disable all when all are enabled                                    |
| Reset-times icon         | Set all tasks' next run times to now                                                     |
| New-task policy selector | Choose on, off or backend-default state for newly added task definitions                 |
| Workflow icon            | Open the full-screen graph editor                                                        |

Bulk enable/disable and reset-times apply to the entire profile's task list, including tasks hidden by search. They do not operate only on search results. Enabling a task does not validate its game configuration. Resetting times can make resource-consuming tasks eligible again.

## Runtime Status

The overview reports the backend's running task and queue. These are not derived from the order currently shown by the frontend. Disabling a task, editing its time or drawing a dependency does not itself send Stop. When changing an active workflow, stop it first if you need the current execution to finish before the change takes effect.

## Detailed Scheduling

The gear dialog stages its own edits. Save applies changed fields and closes the dialog; Cancel or closing it discards that dialog draft. This differs from the automatic-saving feature configuration workspace.

| Field               | Meaning                                                                             |
| ------------------- | ----------------------------------------------------------------------------------- |
| Event name          | Read-only task identity/display name                                                |
| Next run            | Earliest configured eligibility time, not a guarantee of exact wall-clock execution |
| Priority            | Default ordering parameter; smaller values sort earlier                             |
| Interval            | Seconds between eligible executions; enter a nonnegative value                      |
| Daily reset         | One or more daily reset times                                                       |
| Disabled time range | Time ranges during which the task is suppressed                                     |
| Pre-task            | Ordered prerequisite tasks referenced by function identifier                        |
| Post-task           | Ordered follow-up tasks referenced by function identifier                           |

Time and dependency rules are evaluated by the backend scheduler. A queue, an unmet condition, the current task and failure handling can all affect actual execution time. A node positioned to the left is not by itself a scheduling rule.

## Workflow Editor

<img
  className="baas-screenshot"
  src="/media/desktop/en/scheduler-workflow.webp"
  alt="Native workflow editor with task nodes, separate prerequisite and follow-up ports, layout, minimap and zoom controls"
/>

Each task has separate pre-task and post-task port rows. Connect an output on the right to an input of the same kind on the left.

| Connection                            | Stored relationship              | Interpretation           |
| ------------------------------------- | -------------------------------- | ------------------------ |
| A right pre port to B left pre port   | A is appended to B's `pre_task`  | A is a prerequisite of B |
| A right post port to B left post port | B is appended to A's `post_task` | B follows A              |

The editor rejects a self-link, duplicate relationship of the same kind, a cycle, an unknown task and mismatched port types. Existing cycles and missing references loaded from configuration show a warning so they can be inspected.

Select an edge to expose its delete/disconnect control, or use Disconnect in the toolbar. Removing an edge removes that relationship; it does not delete the task. The graph does not bind the Delete key to node deletion.

Drag a node to move it. Use zoom, fit-to-view and the minimap to inspect a large graph. Arrange recomputes the layout and fits the graph into view. Position changes are remembered locally by backend identity and profile, separately from task configuration. Moving or arranging nodes does not change task priority or dependency order.

Relationship changes and task switches patch the backend immediately. Closing the graph is not a cancel operation. Task detail dialogs opened from a node retain their separate Save/Cancel behavior.

## First Run

Start with a small group such as mail or reward collection after checking the correct server and device. Read each feature's settings before enabling shopping, sweeps, combat, friend cleanup or one-shot actions. These tasks can spend currency, AP, tickets or attempts, or modify account state. After each change, inspect the task result and logs before expanding the enabled set.
