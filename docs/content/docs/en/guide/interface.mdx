The desktop window has a narrow navigation rail, a profile and category sidebar, and the current work area. Home, Scheduler and Configuration use the selected profile. Settings applies to the client as a whole. Changing the page does not stop a running scheduler.

## Navigation and Profiles

The rail icons open Home, Scheduler, Configuration and Settings. Hover an icon to read its label. The sidebar button in the titlebar collapses or expands the profile pane; its state is remembered. On wide windows, hovering a navigation icon while collapsed can temporarily reveal its pane. Leaving it or pressing Escape closes the temporary pane. An open menu or dialog keeps it available while being used.

The profile list selects the account, server and device whose data the work area displays. The add-profile icon opens creation; the ellipsis beside a profile opens rename, copy, export and delete actions. Drag profiles to reorder the list. On narrow windows, profiles appear in a horizontal strip with scroll controls. [Profiles](../features/profile) explains archives and account isolation.

The BAAS menu identifies the current workspace. BAAS Raid is shown as in development and cannot be selected; it does not start an alternative raid tool.

## Titlebar Menus

| Menu | Actions and behavior                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| File | Create/import a profile; open the backend configuration folder on supported desktop builds |
| Edit | Undo/redo, cut/copy/paste, delete, select all, and open Settings                           |
| View | Sidebar, back/forward navigation, zoom in/out/reset to 100%, fullscreen                    |
| Help | Documentation and the current help entries                                                 |

Unavailable commands are disabled. Edit commands target the focused editable control or selection. On Configuration, undo/redo can target the profile's configuration history instead; the arrows beside the editor heading expose that same history. Dialogs and profile-run shortcut conflicts affect shortcut handling, so consult [System Settings](../features/system) for the current binding rather than assuming a shortcut is always active.

The titlebar also provides back/forward and native minimize, maximize/restore and close controls. Window framing differs across platforms. Closing or minimizing follows the configured tray preference; leaving the visible window is not a reliable way to stop automation. Use Stop first when the task must end.

## Home Runtime

Home shows the selected profile and server, Start/Stop, task status, assets and logs. Remote Emulator opens the device stream; Hotkeys opens profile-run shortcut configuration.

- Start starts the scheduler for this profile; it does not mean every task runs immediately.
- Stop requests the scheduler to stop. Read the status and logs to confirm the result.
- Running task and queue describe backend state; an empty queue is different from a disconnected service.
- Assets are reported readings with timestamps, not a promise of fresh live game values.
- Log follow and export controls affect the log viewer, not task execution.
- Successful video streaming does not prove the screenshot and input methods used by automation are configured correctly.

See [Runtime and Logs](../features/home-runtime) for detailed behavior.

## Configuration Workspace

Configuration opens an inline editor. The category list and search remain beside it. Settings with several modes use tabs, such as Basic/Cafe 1/Cafe 2. Changes are automatically sent after a short editing pause; there is no general Save button for this workspace. Invalid or unfinished numeric input is kept local until valid.

Use the undo and redo arrows to reverse configuration edits for the selected profile, including edits in another category. History belongs to this window and is not a permanent backend backup. A newly made edit clears the redo branch. [Editing Configuration](./configuration) covers search, automatic persistence, structured editors and profile boundaries.

## Settings Workspace

Settings replaces profile categories with General, Appearance, Shortcuts, Runtime, Updates and Logs. The sidebar stays expanded while Settings is open; leaving Settings restores the previous sidebar preference. Search finds settings across categories and highlights matching controls.

## Connection and Compact Layouts

The lower rail connection indicator reports service state. Open About BAAS for version information. A connected backend and an idle scheduler are separate states: verify the correct profile, tasks and device before running.

At smaller widths, categories use a selector and navigation moves to a compact arrangement. Menus collapse as space decreases. The same profile and editor semantics remain; horizontal or vertical scrolling may be needed for long lists. Android has additional platform-specific startup, game display and permission behavior described in [Android Client](./android).
