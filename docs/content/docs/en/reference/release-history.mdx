This page tracks BAAS Tauri changes across the desktop client, Android client, updater, docs site, and runtime integration. When an issue appears after upgrading, first confirm the version, then check the affected areas and upgrade notes below.

## 0.0.10

This version adds signed Android client updates, stable backend defaults and device-local MirrorChyan CDK management, alongside client interaction and release-workflow improvements. See the [0.0.10 release page](https://github.com/Kiramei/baas-tauri/releases/tag/0.0.10) for packages and publication status.

- New backend installations default to Stable; existing installations retain their saved channel. Development remains available in Preferences.
- Android verifies signed APK downloads before opening the system installer, avoids restarting an active game during reconnection and recognizes Global Teen and ONE store variants. The separate device-launch button is hidden. Device-specific capture and launch limits remain in the [Android guide](../guide/android).
- Android virtual-display focus recovery keeps preview frames advancing after interface interactions and removes temporary focus surfaces. Waiting, black-frame, stalled-frame and error states use only the upper-right badge without covering the game image; tapping the badge opens native controls.
- Desktop and Android store verified MirrorChyan CDKs in private device storage. Stable backend packages are checked against SHA-256 before application. See [update settings](../features/update).
- CI checks follow the changed module, frontend/backend layer and applicable platform. Documentation and README changes use their own checks.
- BAASX supports six OS/architecture combinations with optional npm runtime packages and the `baasx-runtime` helper, retaining legacy-name lookup. Registry installation uses `@kiramei/baasx`; the unscoped name remains on hold. See [BAASX installation](../baasx/installation).
- Profile imports accept ZIPs and folders, preserve existing names with numbered suffixes and safely import `default_config`. macOS uses the native menu bar; wide plugin panes scroll independently.
- Windows portable client updates retain portable mode. Successful managed dependency setup cleans the private UV cache. Profiles retain explicit run failures, desktop notifications group run updates, and appearance settings include BACursors.
- Android Home writes action feedback to profile logs and removes unused space for hidden profile actions. Its task queue keeps the preview visible, and native text selection/copy remains available. App context menus are disabled across Android pages; explicit action menus remain available outside Home.
- Global Settings is now Preferences. Inspect and Reload are removed from app context menus on every platform; Preferences → General provides a Reload button and translated search entries. Configuration dropdowns retain up/down overflow indicators without shifting the list or snapping it back during touch scrolling.
- Client release automation uploads standard Windows installers, macOS DMGs, Linux DEBs and Android ARM64 APKs to MirrorChyan's `baas-tauri` resource and synchronizes release notes. Optional upstream mirroring transfers only platform-named installers as `tauri-<version>` prereleases, excluding Windows portable files, updater archives and signatures while leaving upstream Latest unchanged.

Export important profiles before upgrading. Android APK installation needs system confirmation. Scoped Android 12 ARM64 debug-device checks covered startup, local OCR, the existing `restart` task and preview focus/frame progress; they do not establish full daily-task completion, every gesture, other-device compatibility or long-running reliability.

## 0.0.9.post1

This stable maintenance release improves Android first-run setup, backend installation recovery and startup diagnostics, along with profile initialization, configuration navigation and localization. It also standardizes public and native version ordering. See the [0.0.9.post1 release](https://github.com/Kiramei/baas-tauri/releases/tag/0.0.9.post1) for its published packages and upgrade notes.

## v0.0.9

Use [GitHub Releases](https://github.com/Kiramei/baas-tauri/releases) for published assets, signatures, and release status.

- A shared plugin workspace adds AP hoarding, auto push, equipment planning, the inventory search-board calculator, and Home editing. External ZIPs require per-profile code trust.
- WebUI adds browser login, authenticated Key reset, and Docker deployment. Reset invalidates all existing logins while retaining profiles.
- Desktop, Android, and WebUI gain backend commit history; Help provides client release history. The obsolete `baas-cdn` source is removed.
- Additional settings cover stopping Arena at rank 1, simple-mode stage exploration and story episodes, Cafe interaction delay, and Feishu/WeCom/Telegram notifications. New controls are disabled if the backend lacks their fields.
- Native Windows PC profiles initialize desktop capture/control methods. macOS gains shared-memory transport; Linux window styling and rendering are corrected.
- Android adds same-session native fullscreen manual control, automation-priority input, compute-plugin processes, and navigation/run/update control adjustments. See the [Android guide](../guide/android) for physical-device and emulator validation limits; not every device or task has passed acceptance.
- Bilingual user/API guides are expanded, search is repaired, and desktop showcases use dark WebP images.

Export profiles before upgrading. Plugins and new script fields require a matching backend. Update Docker UI and dependencies by pulling a new image.

## v0.0.8-rc

Prerelease: 2026-09-04. Adds the editable scheduler workflow, minimize to tray, expanded combat and friend-cleanup editors, Windows shared memory, download recovery, and startup/UI fixes. The workflow edits existing scheduler data and persists its layout separately.

See the [RC release notes](https://github.com/Kiramei/baas-tauri/releases/tag/v0.0.8-rc) for Android, WebUI, and updater publication scope. Friend-cleanup filters still depend on the actual backend; read the [deletion warning](../features/maintenance#friend-cleanup) before use.

## v0.0.7

Release date: 2026-07-14

v0.0.7 introduces the native Android client, recoverable service transports, system diagnostics, and notification support. It also fixes Android startup, updater, and frontend rendering issues.

### New Features

| Area | Details |
| --- | --- |
| Android client | Added Android packaging, bundled Python backend, mobile configuration and settings pages, accessibility automation bridge, foreground service controls, notification script toggles, Android updater support, and signed arm64 APK release workflow. |
| Service transports | Added selectable frontend transports, native named pipe support on desktop, shared transport lifecycle events, and recovery after backend disconnects. |
| Diagnostics and notifications | Added frontend system logs, system log settings, script lifecycle notifications, service status notifications, inline terminal output, and richer updater workflow status. |

### Improvements

- Reduced unnecessary React rendering and preserved unsaved configuration drafts.
- Improved home, scheduler, settings, configuration, setup, Wiki, and responsive views.
- Added Android hot development tooling, CSS compatibility processing, backend synchronization, startup handoff, UIAutomator bridging, runtime installation, and backend restart handling.
- Improved Android update byte progress and backend update logs; failed SHA probes no longer block interaction.
- Added signed Android APK publishing, transport build checks, frontend transport tests, and broader quality workflows.

### Fixes

- Fixed Android startup rendering, backend reconnect and restart, relaunch after updates, configuration encoding, Wiki rendering, icon alignment, and local automation bridge behavior.
- Fixed desktop startup blank frames, Tauri development startup, scheduler configuration black screens, and configuration draft loss.
- Fixed script notification snapshots, updater terminal embedding, service log scopes, and transport recovery edge cases.
- Completed missing locale translations and fixed blocking SHA source tests.

### Upgrade Notes

- Android users should check Android installation, permissions, foreground service state, and notification script toggle state.
- Desktop users seeing repeated disconnects should inspect transport mode, backend logs, and system logs first.
- If the UI still shows stale state after updating, restart both client and backend, then confirm version numbers.

## v0.0.6

Release date: 2026-06-28

v0.0.6 rebuilt the docs site, improved appearance customization, enabled portable Windows releases, and polished Wiki, installer configuration, and release workflows.

### New Features

| Area | Details |
| --- | --- |
| Docs site | Added the multilingual docs site with feature guides, install guides, reference pages, screenshots, release download panels, and generated font subsets. |
| Appearance customization | Added image background, theme color, global appearance effect layer, and color picker controls. |
| Windows release | Enabled portable Windows artifacts for users who prefer extracting and running directly. |

### Improvements and Fixes

- Improved the in-app Wiki, docs navigation, home layout, top logo, and scrollbar styling.
- Improved Tauri install config path resolution and setup storage behavior.
- Reworked README content, docs pages, feature descriptions, `setup.toml` references, and install instructions in English and Chinese.
- Fixed install guide links, setup page i18n, Wiki display, docs source behavior, selected link styling, and site styling regressions.

## v0.0.5 and Earlier

Earlier versions established the Tauri desktop client, configuration pages, scheduler, updater, remote display, and release flow. Current docs prioritize the latest stable version. If you are still on an older build, upgrade first before troubleshooting with the current docs.
