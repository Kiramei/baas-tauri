The Tauri installer manages its backend. Manual startup is for source development, isolated testing and independent service deployment. Do not start another process against a live client's ports, configuration directory or device.

## Choose an Entry

| Entry | Behavior |
| ----- | -------- |
| `main.service.py` | Start HTTP/WebSocket and configured local Pipe/shared memory; service commands control scheduling |
| `cli.example.py` | Initialize legacy `Main` and device workers, then run the tasks listed in the script |
| `main.py` | Legacy main-program entry, not a read-only service diagnostic |

Both legacy entries can operate the game. Use Service to test connectivity/authentication, with autostart and tasks disabled. Do not execute the CLI example as a dependency check.

## Prepare an Environment

Create a virtual environment in an independent backend checkout and install Service dependencies:

```bash
python -m venv .venv
python -m pip install -e ".[service]"
```

The second command requires the activated environment's Python; alternatively use its full interpreter path. Project metadata declares Python `>=3.9`, but pinned dependencies and platform constraints still restrict installable combinations. This does not establish support for every newer Python version. [Backend Development](./backend-development) covers the installer's platform dependency lists and OCR. Old instructions fixing Python 3.9.21 and installing generic `requirements.txt` do not describe the current Service dependency split.

## Start Service

```bash
python main.service.py --host 127.0.0.1 --port 8190 --log-level info
```

| Argument | Default and purpose |
| -------- | ------------------- |
| `--host` | `BAAS_SERVICE_HOST`, otherwise `0.0.0.0`; explicitly choose `127.0.0.1` for local development |
| `--port` | `BAAS_SERVICE_PORT`, otherwise `8190` |
| `--log-level` | `info`; Uvicorn logging level |
| `--reload` | Development reload; avoid real tasks and shared runtime directories |
| `--pipe-name` | Enable the named local Pipe; mutually exclusive with `--shm-name` |
| `--shm-name` | Open a managed shared-memory session; mutually exclusive with `--pipe-name` |
| `--ocr-update-check` | Explicitly enable the startup OCR update check |
| `--no-ocr-update-check` | Skip that check, without disabling OCR or accepting missing models |

`BAAS_SERVICE_OCR_UPDATE_CHECK` defaults to enabled. Values `0`, `false`, `no` and `off` disable it; command-line flags override the environment default. Supplying a Pipe/shared-memory argument clears the other local-transport environment variable. Enabling both only through the environment causes startup rejection in the service lifespan.

The client creates and owns local IPC sessions; inventing an endpoint name does not create a usable peer. WebUI still uses authenticated WebSocket. See [local transport boundaries](./backend-service#local-pipe-and-shared-memory).

The script writes `.pid` in its working directory and attempts to remove it on exit. Do not share that file between processes. Ctrl+C requests shutdown, but cleanup and cooperative task stopping can take time. A removed PID file does not establish successful task completion.

### Inspect the Entry Only

```bash
python main.service.py --help
```

Help lists the current build's arguments without starting Service or game tasks. The script still initializes diagnostic logging and runs exit cleanup, so use an isolated directory to avoid touching another process's `.pid`. `GET /health` can inspect a listening service but does not establish authentication, configuration, OCR and device readiness together.

`--host 0.0.0.0` listens on all interfaces. Before remote deployment, initialize the password and configure matching private signing/public frontend keys, HTTPS/WSS, network restrictions and appropriate proxy paths. See [control authentication](./backend-service#control-authentication).

## Legacy CLI Example

Read `cli.example.py` before changing its profile directory and task lists in your isolated copy. To execute a reviewed script, use `python cli.local.py`, or `pdm run python cli.local.py` with PDM.

The current example creates `Main(ocr_needed=["en-us", "zh-cn"])`, `ConfigSet(config_dir="default_config")` and `Baas_thread`, attaches OCR and initializes data. `asyncio.gather()` then schedules two coroutine groups:

| Group | Work |
| ----- | ---- |
| Regular tasks | The script's restart, Cafe, Lessons, rewards, club, mail, both shops, crafting, bounty and other listed tasks |
| Arena | Five Arena tasks, with a 60-second wait after each of the first four |

Device tasks run through `asyncio.to_thread()`. A shared `threading.Lock` serializes `baas.solve()`, so concurrent coroutines do not mean simultaneous device input. These lists/waits are independent of Service scheduler timing and pre/post-task relationships.

The file calls `asyncio.run(main())` at top level: **importing it also executes tasks**. It includes resource-consuming shop operations and is not a side-effect-free library or health probe. The example does not demonstrate a complete exception-recovery/device-cleanup protocol. Scheduled deployment also needs reentry prevention, exit-code handling, timeouts, credentials and private-log handling.

## Validate and Diagnose

Run in an isolated checkout:

```bash
python -m compileall -q service
python -m pytest tests/service
```

Tests create temporary configuration/authentication data. Do not run them inside a directory serving a live client. A successful command proves only its checked scope; network deployment, packaged platforms, OCR models and actual game tasks require separate validation.

For a connected service with no work, check authentication/initialization gates, enabled profile tasks, scheduler state and logs. If scheduling stopped but the process remains, check whether the service should remain resident. Scheduler Stop does not shut down Service. [Backend Development](./backend-development) explains execution boundaries.
