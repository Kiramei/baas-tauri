This is the current **Rust desktop updater** configuration, not a recipe for the legacy Python installer. Normal installs use `<selected-backend-root>/setup.toml`. An existing executable-adjacent file activates portable mode and normalizes the backend root to `"."`; see [Installation](../guide/install#directory-selection-and-startup).

Stop tasks and exit the owning client before manual editing. The app rewrites supported typed fields; concurrent edits can be lost. A MirrorC key, private source URL or machine path makes this file unsuitable for public posting.

## Current Schema

The current schema version is `1`. This complete example uses a Windows-style absolute backend path and WebSocket explicitly so it is not a claim of shared-memory support on every platform. Review the path before using it; portable mode overrides it.

```toml
schema_version = 1

[general]
transport = "websocket"
transport_version = 1
mirrorc_cdk = ""
channel = "stable"
current_baas_sha = ""
current_baas_cpp_sha = ""
get_remote_sha_method = ""
launch = true
force_launch = false
debug = false
no_update = false
git_backend = "auto"
source_list = ["https://pypi.org/simple"]

[paths]
baas_root_path = "D:/BAAS"
tmp_path = "tmp"
toolkit_path = "toolkit"

[repositories]
main_sources = []
cpp_sources = []

[python]
runtime_path = "default"
python_version = "3.9.0"
```

Missing supported fields take their defaults. Empty root paths in a raw default configuration are resolved by the desktop adapter's directory-selection logic; they are not an instruction to run in an arbitrary source checkout. Keep table names lowercase in the current schema.

## General Fields

| Field                   | Type / meaning                                                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `transport`             | `websocket`, `pipe`, or supported desktop `shm`; Windows/Linux default to shared memory, other native platforms to pipe                                         |
| `transport_version`     | Native transport migration marker; current value `1`, not a protocol throughput setting                                                                         |
| `mirrorc_cdk`           | Secret MirrorC delivery key, empty by default; nonempty selects MirrorC rather than the Git path                                                                |
| `channel`               | `stable` or `dev`, default stable; backend delivery/ref selection, not game region or client prerelease selection                                               |
| `current_baas_sha`      | Recorded main backend revision, initially empty; updater-maintained, not a version you should invent                                                            |
| `current_baas_cpp_sha`  | Recorded Cpp/OCR component revision, initially empty                                                                                                            |
| `get_remote_sha_method` | Preferred backend metadata method, initially empty; does not make that endpoint the repository download source                                                  |
| `launch`                | Whether the workflow may launch the service **after preparation**, raw library default false; desktop setup explicitly persists true                            |
| `force_launch`          | Retained boolean compatibility field, default false; no active consumer was found in this audited desktop workflow, so it is not a guaranteed force-kill switch |
| `debug`                 | Retained boolean compatibility field, default false; it is not a supported desktop terminal keep-open control                                                   |
| `no_update`             | Default false; skip main/Cpp repository synchronization and use existing files. It neither creates missing code nor skips all environment/authentication work   |
| `git_backend`           | `auto`, `git_cli` or `git2`; auto prefers system Git and can fall back to Rust git2, explicit CLI needs a working Git executable                                |
| `source_list`           | PyPI index URL list for managed dependency preparation; the built-in default contains multiple indexes, while this minimal example uses one                     |

`no_update = true` is the current repository-freeze control. **Neither `launch = true` nor old `dev = true` means “skip installation/update”.** Do not treat any of these preferences as a network isolation or security boundary.

### Transport Migration

On Windows/Linux, an old unversioned pipe choice can migrate once to shared memory. Explicit versioned pipe and WebSocket choices are retained. Shared-memory configuration copied to unsupported native platforms normalizes to pipe. A supported client choice still requires the corresponding backend implementation; missing `--shm-name` support is a compatibility failure, not an ADB failure.

Use the [client runtime controls](../features/system#connection-and-runtime) for normal changes. Switching transport stops/restarts owned business connections and requires synchronization; it does not change emulator screenshot/control methods.

## Paths, Repositories and Python

| Field                       | Scope                                                                                                         |
| --------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `paths.baas_root_path`      | Backend root; portable deployments force `"."` and change the working directory to the executable's directory |
| `paths.tmp_path`            | Temporary/staging path, default `tmp`, resolved under the root unless absolute                                |
| `paths.toolkit_path`        | Tool directory, default `toolkit`, likewise resolved under the root                                           |
| `repositories.main_sources` | Main repository ranking entries with `url` and integer `order`                                                |
| `repositories.cpp_sources`  | Cpp repository ranking entries of the same shape; `order = -1` means temporarily disabled                     |
| `python.runtime_path`       | `"default"` or an empty/whitespace value selects the managed runtime; otherwise an interpreter path           |
| `python.python_version`     | Managed Python version, current default `"3.9.0"`; does not install dependencies into a custom interpreter    |

Managed mode keeps `.venv` under the backend root and UV under `<toolkit_path>/uv`. A **custom interpreter skips managed UV/Python/venv and dependency synchronization**. You own that environment's compatibility and installed packages; a path string alone is not validation. Do not point it at an unrelated environment expecting the updater to repair it.

Repository updates can replace tracked code. The CLI update path uses a bounded shallow fetch and a hard reset to a validated target; the mirror rollback guard does not preserve local edits. Canonical delivery/ref changes can legitimately change history. Never select a working source checkout as a disposable install destination. Profile backup is separate from saving source changes.

## Source Ranking and Cache

Persisted operational rankings live under `.baas-updater/source-ranking/`: `main.json`, `cpp.json`, `uv.json`, `cpython.json` and `pypi.json`. They are not a global fastest-source league table. Actual operation success can become the preferred URL; failures can disable/demote a source. URL-set changes or exhausted sources can trigger rebuilding and retrying rankings. Preserve source/error context before deleting this evidence.

A valid nonempty CDK chooses MirrorC. Empty chooses Git according to `git_backend`. Successful CDK verification is not proof that every archive or OCR component is available; source/SHA tests and complete installation are separate operations. See [Updates](../features/update).

UV's reusable downloads/builds remain under `<toolkit_path>/uv/cache`. The graph's retained-cache stage is not an automatic full cache purge. A successful requirements cache records normalized requirements/lock paths, their SHA-256 contents and the selected PyPI index in `.baas-updater/requirements-cache.json`. Reuse also requires the lock file. It is not a full installed-environment integrity check and does not hash every installed package. Preserve raw measurement scope when comparing startup timings; see [Performance](./performance).

## Legacy Files and Invalid Configuration

The loader can migrate legacy `[General]` and `[Paths]` files:

| Legacy field                                              | Current destination / behavior                 |
| --------------------------------------------------------- | ---------------------------------------------- |
| `General.dev = true` without an explicit channel          | `general.channel = "dev"`, **not** `no_update` |
| `General.current_BAAS_version` / `current_baas_version`   | `general.current_baas_sha`                     |
| `General.current_BAAS_Cpp_version` / lowercase equivalent | `general.current_baas_cpp_sha`                 |
| `General.runtime_path`                                    | `python.runtime_path`                          |
| `Paths.BAAS_ROOT_PATH`                                    | `paths.baas_root_path`                         |
| `Paths.TMP_PATH` / `TOOL_KIT_PATH`                        | `paths.tmp_path` / `toolkit_path`              |
| `General.git_backend` / `gitBackend`                      | Current Git implementation selection           |

Supported general values such as CDK, source list, launch/no-update and SHA method also migrate. Old `refresh`, `URLs.REPO_URL_HTTP`, `GET_PIP_URL`, `GET_UPX_URL`, `GET_ENV_PATCH_URL` and `GET_PYTHON_URL` are **not equivalent current-schema controls** and are not mapped by this migration. Do not copy the old Python installer's URL table into the new file.

If a current-schema table/marker is present, the loader primarily parses the current schema; it does not merge every legacy table. Avoid mixed schemas. Serialization keeps the supported typed model, not arbitrary unknown extension keys.

The desktop adapter preserves a malformed configuration as `setup.toml.invalid-YYYYMMDD-HHMMSS` and writes defaults when it can recover. That can change channel, update policy, runtime and transport. Inspect the preserved file and the new active configuration before retrying. Filesystem permission/read failures need their own fix; a backup is not proof the previous intended values were retained.

## Developer Contracts

Desktop `SetupPage` requests `updater_get_startup_state`, saves options via `updater_update_config`, waits for the terminal to subscribe, then calls `updater_start_workflow`. Native `baas-updater` produces the plan; `baas-term` owns thread/process tasks and renderer events. The UI does not execute fourteen unrelated shell strings itself.

The dependency graph overlaps main/Cpp repository work with UV/Python preparation, then joins before finalization and dependency work. Node IDs and statuses are authoritative; displayed ordering, a stale pending node, or completion counts are not substitutes for `updater://backend-ready` and authenticated synchronization.

`updater_abort_workflow` cancels owned tasks and removes registered transient paths. It is not rollback for in-place Git updates or installed packages. Saving configuration currently serializes with a filesystem write, not a cross-process transactional configuration store. Avoid simultaneous UI and manual writers.

`updater_reset_backend_auth_and_restart` is a separate destructive credential-recovery operation: it stops the managed backend, removes its authentication/remembered-login/signing/ticket files, restarts and re-authenticates. It is not profile deletion or a general remote-service password reset. Its automatic desktop use and limits are explained in [Installation](../guide/install#completion-and-authentication).

Useful regression boundaries are source/ref change versus stale mirror, failed/late terminal events, cancellation during each graph lane, custom versus managed Python, malformed TOML preservation, backend-ready/authentication separation and no duplicate backend launch. Unit tests with mocked network operations do not replace native package, download and device execution tests.
