Open **Configuration → Stages**. Exploration and Events are two tabs in the same workspace. Editing a plan saves automatically; **Execute starts a one-shot task immediately** and returns to Home. It does not merely enable a scheduler row.

## Exploration Plans

<img
  className="baas-screenshot"
  src="/media/desktop/en/config-stage.png"
  alt="Current exploration tab with manual boss switch, structured normal/hard lists and story commands"
/>

| Control       | Operation / saved field                                                                 |
| ------------- | --------------------------------------------------------------------------------------- |
| Manual boss   | Expects you to handle boss combat rather than assume an unattended clear; `manual_boss` |
| Normal stages | Ordered exploration list; `explore_normal_task_list`                                    |
| Hard stages   | Independent ordered list; `explore_hard_task_list`                                      |

Use **Add chapter**, then choose a chapter and either the whole chapter or an individual mission. New normal choices have missions 1–5; hard choices 1–3. Normal chapters divisible by three also offer mission A. Chapter choices come from the backend's supported range and server maximum, not an unlimited list.

Up/down icons move a row; the trash icon deletes it. Changing chapter keeps a compatible mission, otherwise resets it to whole chapter. Existing values outside the normal choices can remain visible, and unrecognized legacy entries display their raw text. Inspecting them does not repair or validate them; remove or replace stale entries before execution.

### Storage Format

| Target             | Example   | Meaning                                  |
| ------------------ | --------- | ---------------------------------------- |
| Whole chapter      | `15`      | Explore the chapter's supported missions |
| Individual mission | `16-3`    | Explore mission 16-3                     |
| Normal A mission   | `6-A`     | Explore A in normal chapter 6            |
| Ordered list       | `15,16-3` | Chapter 15 followed by mission 16-3      |

These are **not** three-part sweep tokens. `1-1-1` is not the exploration format. [Sweeps](./sweeps) has a separate count-bearing editor.

The normal/hard Execute button rejects an empty corresponding list with an error. Otherwise the client flushes its draft, sends `start_normal_task` or `start_hard_task`, and opens Home. A request acknowledgement is not evidence that the stages completed.

### Prerequisites

Stage exploration follows backend movement routes, not just the game's sweep button. Unlock auto end-turn and auto battle, arrange the correct numbered teams, and use a supported chapter. The normal chapter picker starts from the backend range (commonly chapter 4). Multi-team routes depend on team positions and [selection method](./team).

The backend checks stars, challenges and gifts where its route supports them, and can skip completed targets. Some hard routes need multiple entries to satisfy all goals. This is not a promise that every chapter can finish in one pass or without manual combat.

## Story Commands

| Button      | Immediate backend task |
| ----------- | ---------------------- |
| Main story  | `start_main_story`     |
| Group story | `start_group_story`    |
| Mini story  | `start_mini_story`     |

There is **no main-story chapter-number input in this editor**. Advanced backend profiles can set `main_story_regions`; an empty parsed list makes the audited backend use its server-specific `main_story_available_episodes`. Numeric IDs are backend episode identifiers, not the normal-stage list. Do not paste old episode tables into a nonexistent UI field.

Special story battles and final-chapter mechanics can still require manual play. Stop other tasks before issuing a one-shot story command and watch Home/logs for its actual result.

## Events

<img
  className="baas-screenshot"
  src="/media/desktop/en/config-stage-tab-2.png"
  alt="Current Events tab with event name, Story/Mission/Challenge execution and attack-type data"
/>

The current event name comes from the backend for the selected server. When available, the attack-type table combines its Story, Mission and Challenge entries. No table/name data does not establish that the game currently has no event; backend data can be missing or outdated.

| Action          | Immediate backend task             |
| --------------- | ---------------------------------- |
| Event Story     | `start_explore_activity_story`     |
| Event Mission   | `start_explore_activity_mission`   |
| Event Challenge | `start_explore_activity_challenge` |

These commands start exploration, not event sweeping. Their presence does not prove support for the live event. Confirm the event version, stage structure, server and teams first. Route-map and non-route challenges can need different/manual handling. Activity sweeps and AP allocation are configured under [Sweeps](./sweeps).
