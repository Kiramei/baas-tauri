Open **Configuration → Lessons**. Settings save automatically. The list of
campuses comes from backend data for the profile's server; it is not a fixed
four-campus layout for every server.

## Student and Selection Rules

| Control                | Behavior                                                                                                                                             | Exported field                    |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| Preferred students     | Enable the targeted-student lesson pass before ordinary campus processing                                                                            | `lesson_enableInviteFavorStudent` |
| Preferred student list | Search/Add students, remove a chip, or drag chips horizontally to change preference order; visible only when targeted students are enabled           | `lesson_favorStudent`             |
| Relationship first     | Prefer an available location with more detected relationship opportunities; this does not mean “choose the student with the highest affection level” | `lesson_relationship_first`       |

The student selector applies changes as students are clicked; closing it does
not undo them. Names follow the game server. Disabling preferred students hides
the list but retains its saved names and order; enabling it again shows them.
Targeted lessons use the same
available lesson tickets as ordinary lessons, so the preferred-student pass can
leave fewer or no tickets for the campus table.

## Campus Table

Each row is a campus, with four selectable tiers and an execution count.

| Control      | Values and effect                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| Tier columns | Primary, Normal, Advanced and Superior; click a checkbox to include/remove that tier from the campus rule |
| Count        | Integer 0–99, clamped by the editor; 0 skips this campus in the ordinary pass                             |
| Campus order | Backend/server list order; the count is a requested per-run amount, not a historical counter              |

The tier selections are stored in `lesson_each_region_object_priority`; counts
are stored in `lesson_times`. Higher tiers are considered before lower tiers
when relationship-first is off. Within a considered tier, detected relationship
opportunities can decide which available location is chosen.

In the inspected backend, **an empty tier selection is not a disable switch**:
it falls back to the last available location. Use count 0 to skip a campus.
Relationship-first uses available locations rather than treating these tier
checkboxes as a strict filter. Choose the mode intentionally.

## Tickets and Execution

Ticket purchase count is configured under **Daily sweeps → Sweeps → Ticket
purchases**, not in the campus matrix. Its choices are Skip, a fixed 0–4
purchase count, or Maximum purchases. Maximum may spend the allowed purchase
budget; leaving it selected is not a free-ticket-only policy.

Enable the Lessons task separately. Execution stops when tickets run out or no
suitable location remains. Check the campus name, chosen location, remaining
tickets and completed count in logs. After a server/UI update, capture the actual
unobstructed game screen when reporting recognition failures; a selected table
cell alone does not verify recognition.
