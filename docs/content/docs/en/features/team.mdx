## Choose a Method

| Method                | Stored value | Behavior                                                            |
| --------------------- | ------------ | ------------------------------------------------------------------- |
| By preset             | `preset`     | Select from the in-game preset groups/slots by declared attack type |
| By sidebar attributes | `side`       | Select existing sidebar positions by declared attack type           |
| By sidebar order      | `order`      | Use sidebar teams 1, 2, 3, 4 in route order                         |

The method saves as `choose_team_method`. Preset mode shows only `preset_team_attribute`; sidebar-attribute mode shows only `side_team_attribute`; order mode hides both grids. Switching modes **retains** the hidden values.

## Attribute Grids

Each slot offers Explosive (`burst`), Piercing (`pierce`), Mystic (`mystic`), Sonic (`shock`) and Unused (`Unused`). The localized game terminology may differ. Choose the team's actual attack role, not the enemy armor label. Unused removes the slot from attribute-based candidates; it does not delete that team in game.

Numbered groups and their slot order must match the game. In the audited backend, preset matrix row `i` and column `j` map to preset group `i+1`, slot `j+1`; sidebar slots use their sidebar number. The editor renders the arrays already in the profile, so do not assume every profile has a fixed two-by-four or five-by-four grid. It offers no grid-size editing.

Keep the game's preset numbering recognizable, avoid conflicting students between teams that must deploy together, and provide enough usable teams for multi-team routes. Changing a declaration does not change the actual students.

## Backend Selection and Fallbacks

The route requests attack types; candidate positions are collected in matrix order. The audited backend tries another available type when the requested type is exhausted, following this cycle:

```text
burst → mystic → shock → pierce → burst
```

This is a fallback, not a guarantee of favorable damage. When the **total** declared candidates are fewer than the route's required teams, it logs insufficient presets and falls back to sidebar order. Thus an apparently valid grid can still deploy a different team than expected.

Order mode assumes you already arranged the correct teams in game. For example, the historical normal chapter 20 setup uses team 1 Explosive and team 2 Piercing; a hard route can need a third team. Check the current route rather than applying one arrangement globally.

After a change, supervise a supported stage and confirm the deployed teams in game and logs. Check [Stages](./stages) for immediate commands and [Combat](./combat) for task-specific selectors.
