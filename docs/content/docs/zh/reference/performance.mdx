性能结论需要对应具体测量阶段。请求编码、跨进程传输、状态更新、WebView 渲染和游戏画面识别是不同负载。其中一个阶段更快，不能据此推算完整任务会以同样倍数提速。

## 原生客户端连接

<NativeTransportBenchmark locale="zh" />

前后端运行在同一主机，WebSocket 使用本机回环，不含局域网或互联网链路。

[完整原始记录](/benchmarks/native-transport-current.json)保存了 5,400 次测量、18 次连接切换、分块计时、失败记录、版本与源码文件摘要。客户端是 Windows x64 原生 release 构建，前端提交为 `be186c5`，后端为 `d0a86a0`；环境为 Ryzen 9 9950X、32 个逻辑处理器、31 GiB 内存、Python 3.11.9、WebView2/Edge 155。

负载为生产 Store 的 `trigger("status")` 请求，后端没有运行中的任务。三个业务通道均已初始化。每次回调都返回 `command=status`、`status=ok`、`data={}`，去掉传输外壳和时间戳后的回调 JSON 恰为 44 个 UTF-8 字节；这不是线上的加密包大小。实验覆盖三种方式的全部六种执行排列，每种方式每轮 50 次预热、300 次记录，最多一个未完成请求；切换和同步结束后再等待 1 秒开始预热。

单次计时在 WebView 内从请求准备开始，到生产回调进入时结束。WebSocket 包含实际产品的认证后加密通信；Pipe 和共享内存包含各自的 Rust/Python 传输及 Tauri/WebView 桥接。CDP 仅在每轮前后调度，未放进单次计时。连接切换、初始化、画面渲染和游戏执行均在单次往返之外。

共享内存仍需经过原生 WebView 桥接；底层载体的传输优势不能直接推出这种小请求的结果。图中数据只描述该负载，不能用作大块图像吞吐或所有平台的排名。

实测 `performance.now()` 最小非零步长约 **0.1 ms**，图表保留一位小数。表中的分块值把连续 50 次调用整体计时后除以调用数，包含回调校验与循环开销，减轻单次读数的量化影响；它与单次回调耗时的统计范围不同。p50/p95 使用 `floor(n * p)` 下标，不删离群值。原始记录中的就绪时间还包含停止前一种连接、进程重启、认证和数据同步，属于暖缓存切换时间。它不能当作冷启动数据，也未包含在图中。

测量脚本没有启动并行构建或其他基准测试，主机的其他活动未受控制。这是一台主机、一次会话的描述性结果，没有置信区间；零失败记录不保证长期无故障。

## 当前前端测量

<BenchmarkChart locale="zh" />

图表读取[完整测量记录](/benchmarks/frontend-current.json)，其中保存了准确的源码提交、UTC 时间、环境和每一个样本，而非只有挑选后的平均值。本次环境为 Windows x64、AMD Ryzen 9 9950X、32 个逻辑处理器、系统报告内存 31 GiB、Bun 1.3.14。测量时没有并行进行应用构建。

每个编码样本使用循环字节模式构造一个请求。JSON 基线将字节转换成数字数组并序列化请求；Raw 方法直接调用生产代码中的 `encodeBinaryRequest` 封装函数。负载分别为 1 KiB、64 KiB、1 MiB。每种方法先预热 5 次，再记录 100 次，每轮交替执行顺序。p50/p95 取排序后从 0 开始的 `floor(n * p)` 下标，上限为 `n - 1`。不强制垃圾回收，也不剔除离群值。亚微秒级差异容易受计时精度和运行时噪声影响。

日志对比使用完全相同的 10,000 行输入和 15 轮测量，并断言逐行和批量实现产生的各 scope 日志与全局日志一致。状态通知次数表示这些状态操作，不能当作 React 提交次数。每轮交替方法顺序，保存全部耗时。合成基线模拟原来的逐行更新方式，并非使用旧应用二进制完成端到端测试。

## 复现

在仓库根目录安装锁定版本的依赖后执行：

```powershell
bun docs/scripts/measure-frontend.ts
```

脚本会用新一轮结果覆盖 `docs/public/benchmarks/frontend-current.json`。更换硬件或运行时后发布数据，需要同时更新原始记录与条件说明。单机单轮实验不足以支持适用于所有用户环境的统计推断；本实验没有置信区间。

原生连接实验使用 `docs/scripts/measure-native-transport.mjs`。先准备独立便携副本，核对 `installer-manifest.json` 中记录的二进制 SHA-256，并仅保留一个全部 26 项任务关闭的演示配置。为该副本的 WebView2 开启本地 CDP，进入主页并完成同步后执行：

```powershell
node docs/scripts/measure-native-transport.mjs 19235 "D:/BAAS-benchmark"
node docs/scripts/publish-native-benchmark.mjs
```

脚本会核对 CDP 返回的存储目录与传入根目录，随后重启该副本的受管后端；不能指向日常使用或共享的目录。测量先写入忽略提交的 `.cache/docs-benchmarks/native-transport.json`，最后尝试恢复原传输方式。发布脚本拒绝未完成、未恢复、缺失样本、响应不等价或摘要无法重算的记录。依赖 Playwright 与可连接的实际原生 WebView；更换构建、平台或负载后需要独立记录其版本和条件。

## 前端测量边界

- 操作系统管道、共享内存、跨进程调度、Rust/Python 处理。
- Tauri 到 WebView 的 IPC、浏览器绘制与真实 React 提交耗时。
- 游戏截图、视频解码、OCR、图像匹配和输入发送。
- 网络与更新下载延迟、冷启动、移动端温控和耗电。

不要把这些耗时相加，也不要把它们的比值描述成整个应用或游戏的提速倍数。衡量真实体验时，应固定任务、游戏状态、负载、日志级别、版本和硬件，区分冷暖状态，保留失败，并先验证结果等价。

## 截图与控制的计时边界

脚本调用还经过坐标缩放、随机偏移、截图间隔和识别。下表说明后端适配器的工作范围，耗时不能从上面的状态命令推算。

| 路径              | 计时需要包含的工作                                             | 结果校验                                                          |
| ----------------- | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| ADB 截图          | `screencap -p`、PNG 传输、OpenCV 解码                          | 图像非空、尺寸与颜色正确，画面来自目标设备                        |
| uiautomator2 截图 | 设备端截图、通信、PIL/NumPy 转换、RGB→BGR                      | 返回失败或重试也要记录，不能只保留拿到数组的调用                  |
| Scrcpy 截图       | 流已启动后的新帧等待和图像复制；编码、传输、解码持续在后台进行 | `last_frame_time` 必须晚于调用开始时间，另核对可见画面序号        |
| Nemu 截图         | MuMu 原生 IPC、分辨率查询、像素读取、通道转换和垂直翻转        | 与其他方法的区域、方向、颜色通道和画面序号一致                    |
| MSS / PyAutoGUI   | 窗口激活、区域更新、截图、裁剪/颜色转换                        | 检查遮挡、HDR、DPI、坐标和最终图像尺寸；PC 窗口与模拟器是不同负载 |

`Screenshot.screenshot()` 还会等待截图间隔；配置值小于 0.3 秒时按 0.3 秒处理，间隔从上一次截图完成后计算。只测底层适配器时不包含这段等待，不能据此承诺同样的脚本轮询频率。

控制至少分为三个终点：调用返回、设备接收输入、目标画面出现变化。当前 ADB 点击在调用不足 50 ms 时再等待 50 ms；Scrcpy 点击包含 50 ms 等待；Nemu 点击包含按下后的 15 ms 和抬起后的 35 ms。保留这些生产行为，才能比较用户实际选择的方法。

`Baas_thread.click()` 对非 Nemu 方法默认新建线程并立即返回，只有 `wait_over=True` 才等待线程结束；Nemu 分支同步执行。因此默认 `click()` 的返回耗时不能跨方法直接排名。重复点击、`rate`、`duration`、坐标缩放和约 ±5 像素的随机偏移也会改变工作量。可见响应还应从同一输入开始计时，并识别预期画面状态，避免把任意动画变化记作成功。

当前 Nemu 划动按插值路径和每步等待调度，`duration` 参数没有参与路径生成，需核对实际手势时长。Android 的 `android_local` 则使用内嵌运行时与受认证的本机桥接，不能与电脑端标准 uiautomator2 库混为一种实现；同设备的端口占用说明见 [Android 指南](../guide/android#与电脑端-uiautomator2-共用设备)。

## 传输测试证据

仓库的 `benchmarks/shm-native-cross-process-windows.json` 保存了 Rust/Python 共享内存跨进程测试，不含 WebView 和游戏。1 KiB 往返为 100 次（p50 0.1076 ms，p95 0.1629 ms）；1 MiB 吞吐为 20 次，按双向往返字节计量。这些历史数据与上图测量边界不同，不能合成为统一排名。

`docs/shared-memory-live-validation-2026-10-16.md` 和 `benchmarks/live-game-*.json` 保留历史真实游戏验收。版本和场景属于证据的一部分，不能自动证明新版客户端或 Android 设备的行为与性能。原生 IPC 吞吐结果不能当作游戏帧率。
