## 客户端结构

主要目录：

```text
baas-tauri/
├─ src/                    # React 客户端
├─ src-tauri/              # Tauri 2 Rust 外壳、命令和窗口能力
├─ public/locales/         # 应用 UI 文案
├─ crates/                 # 原生更新器、终端与集成公共 crate
├─ docs/                   # Fumadocs 网页文档站
└─ .github/workflows/      # 发布和文档部署工作流
```

前端主要使用 React、Vite、Tailwind CSS、Zustand、i18next、lucide-react 和 Tauri 2。同步状态仓库通过选中的原生适配器或已认证 WebSocket 传递状态、配置、事件、日志、版本和触发命令。

## 文档站结构

网页文档站位于：

```text
baas-tauri/docs
```

关键文件：

```text
docs/app/docs/[lang]/[[...slug]]/page.tsx
docs/app/docs/[lang]/layout.tsx
docs/content/docs/zh
docs/content/docs/en
docs/lib/source.ts
docs/lib/i18n.ts
docs/public/media
```

路由规则：

- 中文文档位于 `/docs/zh/...`。
- 英文文档位于 `/docs/en/...`。
- 非中文语言在应用内应回退英文。

## 本地开发

文档站命令：

```bash
cd docs
bun install
bun run dev
bun run build
```

本地开发默认地址：

```text
http://localhost:3000/docs/zh/
http://localhost:3000/docs/en/
```

构建产物输出到 `docs/out`。

## GitHub Pages

文档站通过 `.github/workflows/wiki-pages.yml` 构建和部署。工作流会：

1. Checkout 仓库。
2. 配置 GitHub Pages。
3. 安装 Bun。
4. 在 `docs` 目录执行 `bun install --frozen-lockfile`。
5. 传入 `NEXT_PUBLIC_BASE_PATH`。
6. 执行 `bun run build`。
7. 上传 `docs/out`。
8. 部署到 GitHub Pages。

当前独立域名部署使用根路径，构建时的 `NEXT_PUBLIC_BASE_PATH` 由 `actions/configure-pages` 提供。

## 从 baas-dev/docs 迁移

旧 `baas-dev/docs` 中仍有价值的内容包括：

- 安装和更新问题。
- PC 平台截图、HDR、窗口比例和控制方式说明。
- 活动配置、推图配置和编队格式。
- 脚本开发、日志、服务模式和图像资源说明。

迁移原则：

- 用户文档优先写“如何使用当前 Tauri 客户端”。
- 开发细节放在参考页，不混入普通用户流程。
- 旧 UI 截图不直接放入新文档，除非当前界面仍然一致。
- 新功能合并时同步更新中英文文档和截图。

## 文案维护

应用 UI 文案在 `public/locales`，文档文案在 `docs/content/docs`。两者不需要完全同句，但术语要一致，例如：

- 配置档 / Profile
- 调度 / Scheduler
- 服务器 / Server
- 模拟器 / Emulator
- 脚本设置 / Script settings
- 远程模拟器 / Remote emulator
- 推送通知 / Push notifications

中文和英文文档应覆盖同样的功能范围。
