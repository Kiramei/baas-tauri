Android 客户端维护在 `android-dev`，与桌面 `dev` 分开。APK 内嵌前端、Python 运行时、启动适配代码和服务，**不内置完整后端仓库，也不内置 Shizuku 安装器**。首次启动会将配置来源的后端下载到应用私有目录。

## 安装与准备

从项目 [Releases](https://github.com/Kiramei/baas-tauri/releases) 获取可信 Android 构建，按设备真实架构选择，而非只看游戏架构。Android 提示时，为所用浏览器/文件管理器允许安装。核验构建最低要求 Android 7.0/API 24，但最低版本并不保证某设备的特权显示兼容。

首次启动保持网络可用。准备页分五个阶段：

| 阶段         | 实际工作                                          |
| ------------ | ------------------------------------------------- |
| 应用数据     | 准备私有目录，处理受支持的旧数据迁移与备份        |
| 安装运行环境 | 检查内嵌 Python，下载/安装后端并应用 Android 适配 |
| 启动本地服务 | 在独立后端服务进程中启动 Python                   |
| 验证连接     | 建立经过身份验证的加密客户端/后端会话             |
| 同步配置     | 加载配置档与任务，OCR 可继续在后台初始化          |

展开阶段可查看 stdout/stderr 终端。显示“准备中”不代表安装完成；重试前保留完整错误输出，下载、解压或更新时不要强行关闭。

正常运行时和配置保存在应用私有目录，广泛共享存储权限不是启动失败的通用修复。卸载或清除数据可能移除运行时和配置档，操作前先导出需要的配置。

顶部条切换配置档，添加图标用于新建/导入。新建时填写名字，选择与已安装游戏匹配的区服；之后区服不可修改，使用另一游戏包应新建配置档。编辑、复制、导出和删除在配置档菜单中。

底部有首页、任务、配置、设置。中间播放/停止控制当前**调度器**，不仅是预览。首页游戏区域的独立播放按钮只启动游戏后台显示，不启动计划任务。检查消费或删除风险前，先关闭相关任务。

| 配置档区服     | 必须安装的包名                         |
| -------------- | -------------------------------------- |
| 国服官服       | `com.RoamingStar.BlueArchive`          |
| 国服 B 服      | `com.RoamingStar.BlueArchive.bilibili` |
| 国际服         | `com.nexon.bluearchive`                |
| 国际服青少年版 | `com.nexon.bluearchiveteen`            |
| 韩国 ONE 商店  | `com.nexon.bluearchiveone`             |
| 日服           | `com.YostarJP.BlueArchive`             |

区服到包名的映射决定目标。安装另一地区客户端不能替代，应用不会随便使用扫描到的第一个游戏，而会提示目标未安装或区服不受支持。

## Shizuku 授权

从 [Shizuku 官方下载页](https://shizuku.rikka.app/download/)单独安装，根据设备情况启动其服务后返回 BAAS。[官方设置指南](https://shizuku.rikka.app/guide/setup/)说明 root、无线调试及电脑辅助启动方式。

| BAAS 检测状态    | 需要进行的操作                                      |
| ---------------- | --------------------------------------------------- |
| 未安装           | 单独安装 Shizuku，没有可从 BAAS 解出的内置安装器    |
| 已安装但未运行   | 打开 Shizuku 并启动服务                             |
| 正在运行但未授权 | 在 BAAS 点击允许访问，再确认真正的 Shizuku 权限弹窗 |
| 已就绪           | 关闭提示，再明确重试原来的启动动作                  |
| 状态检查失败     | 查看错误并重试检查，不要凭旧 Live 标志认定授权有效  |

启动调度和启动后台游戏都会检查当前权限。授权后不会暗中续执行之前被阻止的命令；停止调度是独立操作，权限失效时仍应能够停止。

**使用当前安装的 Shizuku 界面提供的启动指令。** 旧说明使用外部 `start.sh`，[v13.6.0](https://github.com/RikkaApps/Shizuku/releases/tag/v13.6.0) 已改用安装目录内的原生可执行文件。不要复制另一设备的安装路径。本次模拟器测试使用管理器实际显示的命令，并通过原生弹窗授权。

## 后台游戏与预览

授权后选中匹配配置档，点击首页游戏区域的播放图标。BAAS 创建本机后台显示并启动对应包；该显示是共享资源，另一配置档正在运行时会阻止冲突启动。恢复出来的旧显示也不能自动视为属于当前配置档。

原生预览是**只读的**。点击画面会打开三个原生图标：

| 图标动作 | 设计行为                                             |
| -------- | ---------------------------------------------------- |
| 关闭     | 结束 BAAS 后台显示，不等同于停止调度器               |
| 接管     | 把已有游戏任务移到主显示供手动操作，随后释放嵌入会话 |
| 重启     | 关闭当前后台会话，再准备所选游戏                     |

点击预览里的游戏按钮不会直接发送游戏输入；需要手动操作时使用接管。菜单和弹窗出现时会隐藏原生预览，避免覆盖界面控件；回到可见首页后恢复预览归属。切到其他页面隐藏的是视图，不一定停止后台游戏或 Python 服务。

Live 只说明显示状态，**不能证明**游戏已登录、输入有效或任务成功。加入调度前核对真实画面及游戏所在显示。

## 生命周期与通知

Python 由独立后端服务持有，不由 Activity 持有；WebView 重载或 Activity 重建应重新连接，而不是再启动一个 Python 所有者。系统返回键先处理弹窗和页面导航，再可能将 Activity 放到后台，不是调度停止按钮。

前台服务使用低优先级常驻通知，点击可打开应用；**没有通知栏启动/停止任务动作**。其 Shizuku 初始化还会尝试抑制 BAAS 通知，因此是否出现在通知抽屉不能单独作为健康指标。使用应用内连接/运行状态和系统日志判断；系统后台限制仍可能终止工作，短时测试成功不代表长期运行可靠。

## 更新与排查

后端更新使用应用配置的来源，并显示进度和输出；失败时保留启动、系统及更新日志。下载请求失败、身份验证失败、游戏识别失败属于不同层，调截图间隔不能修复下载。

| 现象               | 核对项目                                               |
| ------------------ | ------------------------------------------------------ |
| APK 无法安装       | 真实 CPU ABI、Android 版本、可信安装权限、已有包和签名 |
| 准备失败           | 对应阶段终端、网络/来源、应用私有存储                  |
| 游戏未安装提示     | 当前配置档精确对应的地区包名                           |
| Shizuku 不可用     | 安装、运行、授权三个独立状态                           |
| Live 但黑屏/启动图 | 实际游戏任务与显示归属、原生采集错误、ABI 兼容         |
| 后端断连           | 服务/进程日志及后台限制，不仅看通知是否显示            |

## 模拟器 ABI 兼容

部分 x86_64 模拟器可安装 ARM64 应用，但 Shizuku 用户服务仍运行于 x86_64 进程。加载 ARM64 采集库时会出现 `EM_AARCH64` 与 `EM_X86_64` 不匹配错误，需要使用与该进程架构匹配的构建。游戏停在启动图时，还应检查游戏 Activity 的显示归属与原生采集日志。

更多排查见[故障排除](../reference/troubleshooting#android-客户端异常)。
