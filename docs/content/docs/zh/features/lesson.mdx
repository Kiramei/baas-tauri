并不是所有区服都固定为四个校区。

## 学生与选择规则

| 控件         | 行为                                                                         | 导出字段                          |
| ------------ | ---------------------------------------------------------------------------- | --------------------------------- |
| 偏好学生     | 在普通校区处理前启用指定学生的日程流程                                       | `lesson_enableInviteFavorStudent` |
| 偏好学生列表 | 搜索并添加学生、移除标签，或横向拖动标签调整偏好顺序；仅在启用偏好学生时显示 | `lesson_favorStudent`             |
| 好感优先     | 优先选择检测到好感机会更多的可用地点，不是“选择好感等级最高的学生”           | `lesson_relationship_first`       |

学生选择器每次点击都会应用修改，关闭不会撤销。名称遵循游戏区服。
关闭偏好学生会隐藏列表，已保存的学生和顺序保留，重新启用后继续显示。
指定学生流程与普通日程使用相同的票券，因此优先处理学生后，校区表可能
只剩较少票券或完全没有票券。

## 校区表

每行对应一个校区，包含四个可勾选等级和执行次数。

| 控件     | 值与效果                                                           |
| -------- | ------------------------------------------------------------------ |
| 等级列   | 初级、中级、高级、特级；点击复选框将该等级加入或移出这个校区的规则 |
| 次数     | 整数 0–99，编辑器会限制范围；0 跳过普通流程中的这个校区            |
| 校区顺序 | 使用后端与区服提供的顺序；次数是本轮计划次数，不是历史累计次数     |

等级选择存储在 `lesson_each_region_object_priority`，次数存储在
`lesson_times`。关闭好感优先时，先考虑较高等级，再考虑较低等级；
同一考虑等级内，可根据检测到的好感机会选择可用地点。

核对的后端中，**等级全部取消不代表禁用校区**，而会回退到最后一个可用地点。
需要跳过校区时应将次数设为 0。好感优先依据可用地点选择，
不会将等级复选框当作严格过滤条件，设置时需明确采用哪种规则。

## 票券与执行

票券购买次数在**每日扫荡 → 扫荡 → 票券购买**中配置，不在校区表内。
可选择跳过、固定 0–4 次购买或最多购买。最多可能花费允许范围内的购买预算，
不是“仅使用免费票券”。

需要另行启用日程任务。票券耗尽或没有合适地点时流程会结束。
查看日志中的校区名、选中地点、剩余票券与完成次数。区服界面更新后若出现
识别问题，应提供无遮挡的实际游戏画面；表格已勾选不代表识别一定成功。
