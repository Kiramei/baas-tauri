## 选择编队方式

| 方式       | 存储值   | 行为                                 |
| ---------- | -------- | ------------------------------------ |
| 按预设编队 | `preset` | 根据声明属性，选择游戏内预设组及位置 |
| 按侧栏属性 | `side`   | 根据声明属性，选择已有侧栏队伍位置   |
| 按侧栏顺序 | `order`  | 按路线顺序使用侧栏第 1、2、3、4 队   |

方式保存为 `choose_team_method`。预设方式只显示 `preset_team_attribute`，侧栏属性方式只显示 `side_team_attribute`，侧栏顺序方式隐藏两张表。切换方式**保留**隐藏数据。

## 属性矩阵

每个位置可选爆发（`burst`）、贯穿（`pierce`）、神秘（`mystic`）、振动（`shock`）和未使用（`Unused`），具体译名随界面语言变化。填写队伍实际攻击定位，不是直接填敌方护甲名称。“未使用”使该位置不参与属性候选，不会删除游戏队伍。

编号组和组内顺序应与游戏一致。核验后端中，预设矩阵第 `i` 行、第 `j` 列对应从一开始编号的第 `i+1` 个预设组、第 `j+1` 个位置；侧栏位置使用对应侧栏编号。编辑器按配置现有数组显示，不能假定所有档都是固定两行四列或五行四列，也没有修改矩阵尺寸的控件。

保留游戏可识别的预设编号，避免需要同时出战的队伍出现学生冲突，并为多队路线准备足够队伍。修改属性声明不会自动改变队员。

## 后端选队与回退

路线提出所需属性，候选队伍按矩阵顺序收集。核验后端在某属性用尽时，会沿以下循环寻找其他可用属性：

```text
爆发 → 神秘 → 振动 → 贯穿 → 爆发
```

这是后备选择，不保证伤害克制。当声明的**全部**候选数量少于路线需求时，后端记录预设不足并回退到侧栏顺序。因此，即使矩阵看起来填写完整，也可能部署非预期队伍。

侧栏顺序方式要求你提前在游戏中排好正确队伍。例如旧资料中的普通第 20 区使用第 1 队爆发、第 2 队贯穿，困难路线可能另需第三队；请核对当前路线，不要把同一种安排套用到所有区域。

修改后监督一个受支持关卡，通过游戏与日志核对实际部署。[推图](./stages)说明立即执行命令，[战斗](./combat)说明各任务专有的队伍选择。
