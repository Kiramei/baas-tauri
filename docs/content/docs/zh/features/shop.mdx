打开**配置 → 商店**。两个选项卡分别编辑独立购买方案，修改自动保存，
对应商店任务需要另在调度中启用。勾选商品表示消费指令，不是推荐购买标记。

## 商品与刷新

| 选项卡     | 商品选择字段                | 刷新次数字段                       |
| ---------- | --------------------------- | ---------------------------------- |
| 普通商店   | `CommonShopList`            | `CommonShopRefreshTime`            |
| 竞技场商店 | `TacticalChallengeShopList` | `TacticalChallengeShopRefreshTime` |

点击商品格选中，再点一次取消，勾选标记与按下状态表示已选。
每格显示后端提供的商品名称、价格与货币。普通商品可能消耗信用点或青辉石，
竞技场商品消耗竞技场币。商品列表由配置档区服决定，
界面语言不一定会翻译每个商品名称。

四列网格保留游戏内商品位置，选中状态是按位置保存的 0/1 列表，
不是购买优先级排序，也不是任意数量输入框。
切换游戏区服、导入旧配置档或更新商店定义后，应重新核对位置。
没有选中商品时，对应任务会直接结束而不购买；
提高刷新次数不会自动添加商品。

## 刷新次数与消耗

编辑器接受 0–5 的整数并限制输入范围，暂时留空的草稿不保存。
0 表示首轮购买后不刷新，不表示“不购买”。
每次额外刷新可能再次购买同一组选中商品，并另行消耗刷新货币。

核对的 Python 后端将**两个商店**的刷新次数都限制为最多 3 次，
虽然当前界面允许填写到 5。因此在这个后端版本上，填写 4 或 5
不代表实际执行四次或五次刷新。普通商店实现的刷新消耗为
40/60/80 青辉石，竞技场商店为每次 10 币。
游戏更新后，应以实际确认界面与当前后端实现为准。

普通商店检查所选商品需要的货币，竞技场商店检查竞技场币。
余额不足或购买不可用时可以提前结束；配置次数是请求上限，
不保证每轮都会发生。

## 验证购买方案

先将刷新次数设为 0，逐一核对所选格子的货币。
单独运行目标商店任务，检查游戏与日志中的已购商品和余额变化，
再决定是否增加刷新次数。刷新为 0 仍可能花费青辉石，
例如首轮就选中了青辉石商品。这两个选项卡不代表已覆盖游戏内所有其他商店。
