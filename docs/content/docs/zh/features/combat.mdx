在**配置**中选择对应战斗分类。有效修改自动保存，没有单独的保存弹窗；修改配置本身不会开战。确认队伍、票券和当前 Boss 的支持情况后，再到[任务](../guide/scheduler)启用。

## 竞技场

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-arena.webp"
  alt="新版竞技场编辑器：等级差、最大刷新次数与对手位置"
/>

| 控件         | 取值                 | 实际作用                             |
| ------------ | -------------------- | ------------------------------------ |
| 等级差       | `-89` 至 `89` 的整数 | 检查对手等级时使用的阈值             |
| 最大刷新次数 | 大于等于 `0` 的整数  | 限制寻找对手的刷新循环，不是战斗票数 |
| 对手序号     | `1`、`2`、`3`        | 最终挑战的对手位置                   |
| 第一名停止挑战 | 开启或关闭 | 已经排名第一时领取可领取奖励，跳过后续挑战，不消耗战斗票券 |

核验的后端使用条件 `对手等级 + 等级差 <= 自身等级`。例如自身 90 级，填 `10` 表示要求对手不高于 80 级；填 `-5` 则允许到 95 级。正数并非允许对手比自己更强。

**等级条件不是保证跳过战斗的保护开关。** 刷新次数耗尽后，后端仍会挑战指定位置；填 `0` 只是跳过寻找循环，并不会关闭竞技场。无票时领取可领取奖励后返回；核验流程中没有自动购票。

数值输入为空、小数或超出范围时，会阻止该分类草稿提交。导出字段为 `ArenaLevelDiff`、`maxArenaRefreshTimes`、`ArenaComponentNumber`，以及布尔值 `ArenaStopFightWhenRank1`。如果当前后端配置快照没有第一名停止挑战字段，开关会禁用并提示更新后端。

## 总力战

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-tactical.webp"
  alt="总力战内联编辑器的难度选择"
/>

这里只有难度控件（`totalForceFightDifficulty`）。选项由连接的后端和当前区服提供，已知标签包括 NORMAL、HARD、VERY HARD、HARDCORE、EXTREME、INSANE、TORMENT，但不能假定所有后端都提供全部难度。旧配置中不在当前列表里的值也可能继续显示。

能选中某个难度，不代表当前 Boss 攻略、借人流程或自己的队伍能够通关。先监督验证受支持的战斗，再加入调度；难度过高可能消耗次数而无法完成。

## 综合战术考试

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-drill.webp"
  alt="综合战术考试：剩余票券扫荡开关、出战队伍编号和难度"
/>

| 控件               | 操作与影响                                     |
| ------------------ | ---------------------------------------------- |
| 战斗后扫荡剩余票券 | 允许配置的战斗结束后继续扫荡，可能消耗剩余次数 |
| 出战队伍编号       | 每次出战选择游戏内 `1`–`4` 号队伍              |
| 难度               | 在对应位置选择 `1`–`4` 级难度                  |

第一个队伍编号对应第一个难度，第二个对应第二个，以此类推。显示数量由现有配置数组决定，通常为三组；编辑器不提供增删出战行。它不会自动编入学生，也不会检查队伍战力。

保存字段为 `drill_enable_sweep`、`drill_fight_formation_list`、`drill_difficulty_list`；数组值必须是 1 至 4 的整数。

## 制约解除决战

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-finalRestrictionRls.webp"
  alt="制约解除决战的编队方式及按条件启用的复制设置"
/>

| 控件             | 取值和显示条件                                               |
| ---------------- | ------------------------------------------------------------ |
| 编队方式         | 使用当前编队（`default`）或复制通关编队（`copy_clear_unit`） |
| 最大未持有学生数 | `0`–`10` 的整数，默认 `0`，仅复制方式下可编辑                |
| 最大刷新次数     | 非负整数，默认 `10`，仅复制方式下可编辑                      |

切回当前编队后，两个数字输入框禁用但保留数值。即使禁用，数值仍需合法。

**后端兼容性**：核验的桌面客户端已有这些控件，但本次使用的默认后端快照中未找到对应任务和字段实现。保存成功不能证明复制编队或任务能够执行；请先确认实际连接的后端已实现，再启用任务。

导出键为 `final_restriction_rls_employ_formation_method`、`final_restriction_rls_employ_formation_copy_clear_unit_max_unavailable_student_count`、`final_restriction_rls_employ_formation_copy_clear_unit_max_refresh_count`。

## 加入调度前

停止已有运行，核对当前配置档和区服，设置[队伍](./team)，并监督一次执行结果。刷新上限、难度菜单和配置确认回执都不是游戏任务已成功完成的证明。
