## 启动与结束动作

| 控件       | 保存字段    | 含义与限制                                            |
| ---------- | ----------- | ----------------------------------------------------- |
| 自动运行   | `autostart` | 保存旧后端/启动器的启动标志，不是操作系统开机启动注册 |
| 结束后动作 | `then`      | 无动作、退出 BAAS、退出模拟器、退出两者、关闭主机     |

核验的 Tauri 客户端中，配置编辑器以外未找到读取 `autostart` 并在启动时执行的逻辑。因此不要仅凭此开关建立无人值守启动预期，需验证实际后端/启动器行为。

结束动作即使在英文界面，也保存后端字符串 `无动作`、`退出 Baas`、`退出 模拟器`、`退出 Baas 和 模拟器`、`关机`。核验后端在调度器判断后续等待足够长时处理 `then`，不是每个单项任务结束都执行。

**关机与退出会影响真实运行环境。** 测试时保留“无动作”；保存结束动作不是确认预览，也不能假定 Android 会以桌面相同方式关闭模拟器或主机。

## 截图间隔

`screenshot_interval` 是后端识别截图的间隔，单位为秒，需为不小于 `0.1` 的有限数。留空、非数字或更小数值会阻止该分类草稿提交；输入步长为 0.1。

它不是游戏 FPS、预览 FPS、视频码率，也不保证固定的端到端反应时间。减小间隔会提高请求截图的频率，但实际行为还受处理、传输和游戏切屏影响。测量范围见[性能](../reference/performance)，不要直接推断固定加速比例。

## 截图方式与控制方式

两个下拉框使用后端提供的支持列表。旧配置中未知方式会保留显示，不代表当前环境一定可用。

| 方式         | 截图与控制场景                               |
| ------------ | -------------------------------------------- |
| ADB          | 通过 ADB 获取设备画面、发送输入              |
| Nemu         | MuMu 专用截图/控制集成，要求环境匹配         |
| uiautomator2 | 设备自动化连接，后端与设备准备需对应         |
| scrcpy       | 设备视频和控制集成，视频解码可能影响识别画质 |
| MSS          | 桌面屏幕截图，不是设备输入方式               |
| PyAutoGUI    | 桌面截图与鼠标输入，受窗口位置和焦点影响     |

保存字段为 `screenshot_method`、`control_method`，选择器下方说明随方式变化。并非每个后端/平台都提供所有选项，同一种方式也不一定同时出现在两表中。选择兼容组合后验证实际截图和点击；修改下拉框不会代为安装驱动。

日志反复出现 `tentative click` 却不前进时，检查实际画面、目标窗口/设备、控制方式和遮挡。坐标或识别图不对时，不要只持续提高点击频率。

## 识别基准设置

历史后端指南使用稳定的 16:9 画面，常见为 `1280×720`、60 FPS、兼容渲染、开启后处理/抗锯齿、关闭战斗黑边。这些是识别环境参考，**不是本次性能基准测试结果**；请核对当前游戏实际提供的选项，不要假定所有版本标签相同。

动态回忆大厅、HDR/颜色变换、覆盖层，以及修改按钮和文字的汉化补丁都可能让截图偏离模板。先恢复未修改、清晰可见的游戏界面，再排查任务逻辑。

## Android

Android 隐藏截图和控制方式选择器，内部使用 `android_local`；编辑器只提交公共字段，不覆盖桌面的方式字段。本地截图/输入需要正在运行且已授权的 Shizuku 及正确的配置档游戏显示，不是选择桌面 ADB。详情见 [Android 客户端](../guide/android)。
