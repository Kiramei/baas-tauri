title: 扫荡
description: 结构化普通/困难计划、悬赏和学园交流次数、活动体力占比、旧值保留与付费购票。

打开**配置 → 日常扫荡**。第一个选项卡编辑普通/困难关卡计划；第二个编辑悬赏、学园交流、特别委托、活动和购票次数。有效修改[自动保存](../guide/configuration)，不会立即执行；还需在[任务](../guide/scheduler)中启用对应任务。

扫荡消耗体力或票券，并要求游戏已解锁扫荡、关卡满足通关条件。加入每日调度前先测试较小次数。

## 普通与困难计划

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-dailySweep.webp"
  alt="新版日常扫荡计划：按行选择区域、关卡和次数"
/>

每行包含区域、关卡和次数，按显示顺序执行。加号添加关卡，上下箭头调整顺序，垃圾桶移除；首尾行不能移出列表。

普通和困难计划分别保存为 `mainlinePriority` 和 `hardPriority`。

| 字段     | 合法值                                            |
| -------- | ------------------------------------------------- |
| 区域     | 正整数；后端提供普通/困难区域上限时受该上限约束   |
| 普通关卡 | `1`–`5`                                           |
| 困难关卡 | `1`–`3`                                           |
| 次数     | 非负整数，`0` 表示跳过                            |
| 最大次数 | 支持时可选 `max`，使用可用体力/次数，不是预留资源 |

**当前客户端的国服/B 服困难计划不允许 `max`**；普通计划以及国际服、日服困难计划允许。旧配置中存在不受支持的 `max`，不代表实际后端能执行。

导出仍使用逗号分隔的 `区域-关卡-次数`，如普通计划 `15-3-3,20-3-max`。困难也是三段格式，但有上述区服限制；不要与[推图](./stages)的格式混用。

无法识别的旧行会保留原文并显示错误，打开计划不会自动改写。编辑后的计划需先修复或删除非法项才会提交，临时非法输入保留在本地。

### 按学生查找困难关卡

打开学生辅助选择，搜索并选择名字后，选择器关闭，并追加后端数据中该学生对应的所有困难关卡。新行默认扫荡三次，已有行的次数和顺序不变；相同区域/关卡不重复追加，无法识别的旧项保留。学生名来自后端区服数据，不一定随界面语言翻译。此操作不保证关卡已解锁或必定掉落神名文字。

## 按位置配置次数

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-dailySweep-tab-2.webp"
  alt="扫荡详情选项卡中的悬赏及各区域次数控件"
/>

| 组别     | 顺序和数量                                      | 保存字段              |
| -------- | ----------------------------------------------- | --------------------- |
| 悬赏通缉 | 按界面区域标签；国服/B 服、国际服三项，日服五项 | `rewarded_task_times` |
| 学园交流 | 圣三一、格黑娜、千年                            | `scrimmage_times`     |
| 特别委托 | 据点防御、物品回收                              | `special_task_times`  |

模式选择器提供**跳过**（`0`）、**固定次数**和**全部可用**（`max`）。固定次数使用整数；悬赏也接受零。`max` 不会凭空增加票券或体力。

旧的三项日服悬赏配置保留前三项，新增两项显示为零。次数编辑器无法表示的旧值会原样显示，并提供明确的替换命令；替换会把该组重置为全零，不只是调整格式。旧的负数位置次数可能显示为跳过，编辑前不会自动改写。

删除旧计划行或重置旧次数后，可使用配置撤销恢复原文。先核对整组规则，
再决定是否替换；重置后的零值会跳过该组。

## 活动扫荡

<img
  className="baas-screenshot"
  src="/media/desktop/zh/config-dailySweep-tab-2-scroll-2.webp"
  alt="详情下方的活动关卡、次数模式及购票上限"
/>

活动关卡选择器使用后端当前活动中可识别的任务列表；没有可用列表时显示正整数输入框。旧配置中不属于当前活动的关卡可能作为“已保存”选项保留，不代表活动实际可用。

| 模式             | 存储示例           | 含义                             |
| ---------------- | ------------------ | -------------------------------- |
| 跳过             | `0`                | 不扫荡此项                       |
| 固定次数         | `3`                | 请求三次扫荡                     |
| 体力占比         | `0.5` 或旧值 `1/3` | 按初始体力预算的占比计算         |
| 全部已选活动关卡 | 单独一个 `-1`      | 对每个所选关卡计算相同的扫荡次数 |

占比输入范围为 0–100%。**整数 `1` 是扫荡一次，小数 `1.0` 是使用 100% 体力。** 活动次数不使用普通计划的 `max`。只有一项次数时才提供“全部”活动模式；旧的多项次数列表中的 `-1` 不会触发均分。

高级配置可以在 `activity_sweep_task_number` 保存关卡列表，在 `activity_sweep_times` 保存对应次数列表。当前界面主要选择一个活动关卡，不是完整的多关卡列表编辑器。旧列表长短不一致时，核验的后端只执行两者能配对的前面部分。

### 体力计算与限制

核验的后端在循环前读取一次体力，占比目标向下取整：

```text
目标次数 = floor(初始体力 × 占比 / 单次体力消耗)
```

例如 999 体力、每次 20 体力，`0.5` 计算为 24 次，`1/3` 为 16 次。这是计算示例，不是游戏实测结果。前面的关卡消耗同一份真实体力，后续项可能因不足而停止；每项不会重新获得独立体力预算。

单独的 `-1` 按 `floor(体力 / 所选关卡单次体力之和)` 计算**每关**次数。不同耗体关卡均分的是扫荡次数，不是每关体力。实际消耗来自当前活动数据，不能假定所有活动固定为 10/15/20 体力。

**当前后端限制**：活动目标超过 50 次时，核验实现会将其替换为 `floor(初始体力 / 该关单次体力)`。较大的固定次数因此可能比设置值暗示的更耗体力。除非实际后端已修正该行为，否则使用较小目标并监督；体力不足或未满足扫荡条件时也可能停止或跳过。

## 购买票券

| 购买类别   | 界面选项                 | 保存字段                              |
| ---------- | ------------------------ | ------------------------------------- |
| 悬赏票     | 跳过 `0`、`1`–`12`、最大 | `purchase_rewarded_task_ticket_times` |
| 课程表票   | 跳过 `0`、`1`–`4`、最大  | `purchase_lesson_ticket_times`        |
| 学园交流票 | 跳过 `0`、`1`–`12`、最大 | `purchase_scrimmage_ticket_times`     |

这些是**购买上限**，不是免费发票或已完成扫荡次数。“最大”保存为 `max`，允许后端按游戏和资源限制购买最大可用数量。没有明确消费意图时保留零。课程表购票虽在此设置，实际由[课程表](./lesson)任务使用。

所有组共用一个草稿。悬赏次数非法、活动关卡为空或其他已修改字段非法，都可能阻止该分类的其他修改提交。先修复输入并核对连接状态，再认定后端已接受新配置。
