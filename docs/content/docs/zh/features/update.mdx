## 推荐更新顺序

### 检查版本信息 [step]

先确认后端版本、客户端版本和当前配置档状态，避免在任务运行中直接更新。

### 选择更新通道与更新源 [step]

日常使用优先选择稳定版；如果 GitHub 访问不稳定，再切换可用镜像或 MirrorC。

### 运行 SHA 测试 [step]

用 SHA 测试确认当前更新源能获取版本信息。测试失败时，不要继续更新，先换源再重试。

### 停止调度并执行更新 [step]

更新前停止正在运行的任务，避免后端文件、日志或状态在执行过程中被替换。

### 重启后验证版本 [step]

更新完成后重启客户端或后端，回到版本信息区域确认新版本已经生效。
