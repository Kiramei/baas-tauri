打开**设置 → 更新**，后端代码与原生客户端是两种更新对象。检查成功不等于安装，检查失败也不代表已是最新；版本变更见[版本历史](../reference/release-history)。

原生工作流、文件替换、取消和信任边界见[更新器内部机制](../reference/updater-internals)。

## 版本组与动作

| 对象       | 展示和动作                                                    |
| ---------- | ------------------------------------------------------------- |
| 后端脚本   | 本地/最新提交缩为六位，完整详情在提示中；按通道和 SHA 查询偏好检查，原生可回退其他查询源 |
| 原生客户端 | 当前/最新版本及检查、错误、可更新状态；可用更新时动作变为安装 |
| WebUI      | 可查看后端，没有原生客户端安装动作                            |

切换来源/通道后重新检查。空值、检查中、错误或禁用检查都不能证明版本相等；后端提交与客户端版本号也不能直接比较。

后端有更新时，桌面和 WebUI 的侧栏脚本更新动作（或紧凑/悬浮入口）先请求停止全部任务并等待停止状态。原生桌面随后重载，进入托管启动/更新流程；WebUI 使用后端流式更新。Android 手动入口提前进入自己的 git2 工作流和终端，跳过这段 `stopAllTasks`，不能据此认定任务已停止。

**Android 手动更新后端前，请先停止全部配置档的任务，并确认各档均已停止。**

Android 同步成功后调用的 `updater_reset_backend_auth_and_restart` 返回 `restarted: false`、`restart_deferred: true`，仅确保服务存在。随后 WebView 重载会重连现有服务，已加载的 Python 模块仍在原服务进程中；磁盘提交变化不能证明新代码已经运行。空闲自动更新有独立的停止与恢复流程，见下文。

部分 Android 服务文件由 APK 匹配的 `backend-service-overlay` 优先提供。更新后端仓库不会替换这些文件；重启后也需核对客户端版本和实际模块来源。服务覆盖层见[更新器内部机制](../reference/updater-internals#android-服务覆盖层)。

原生客户端安装也会请求**停止全部任务**，等待停止状态，下载/安装后通常重启桌面应用。下载百分比不是整体安装/重启百分比；进度报错需排查，关闭进度视图不等于已提供取消机制。Android APK 安装按平台处理，不能照桌面重启流程解释。

Android 会重新检查远端版本高于当前客户端，下载 HTTPS APK 并用内置公钥验证 Minisign 签名，再交给系统安装器。缺少“允许来自此应用的安装”权限时会打开授权页并返回错误，授权后需重新发起更新。成功返回或进度完成只说明安装器已打开；系统安装可被取消，完成与否需要以后续启动的客户端版本确认。当前下载命令没有取消接口，关闭进度视图不停止下载。

## 来源与通道

以下属于共用后端设置，不是单档游戏策略：

| 字段           | 含义                                    |
| -------------- | --------------------------------------- |
| `updateMethod` | 来源控件值；后端映射到 `general.get_remote_sha_method` |
| `channel`      | `stable` 或 `dev`，解析为配置的仓库引用 |
| `shaMethod`    | SHA 查询偏好；映射到同一个 `general.get_remote_sha_method` |
| `mirrorcCdk`   | 已验证 Mirror 酱密钥，按敏感数据处理    |

两个控件共享持久化字段，无法独立保存；同一补丁同时提供两个值时，`updateMethod` 后写入。原生 Git 下载单独对候选仓库 URL 选源并保存成功来源，不受该字段固定。桌面以非空 CDK 选择 Mirror 酱，其请求当前固定为 `stable`，即使界面选择 `dev`；Android 仓库工作流强制 git2 并清空 CDK。来源控件、SHA 探测和实际下载路径需要分别判断。

当前客户端的来源选项为：

| 名称                               | 标识                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| GitHub                             | `github`                                                 |
| CNB                                | `cnb`                                                    |
| Gitee                              | `gitee`                                                  |
| GitCode                            | `gitcode`                                                |
| GitHub v4、v6、CDN 加速            | `github_proxy_v4`、`github_proxy_v6`、`github_proxy_cdn` |
| gh-proxy.org                       | `gh_proxy`                                               |
| SevenCDN                           | `sevencdn`                                               |
| GitHubFast                         | `githubfast`                                             |
| BAAS CDN                           | `baas_cdn`                                               |
| 有已验证存储密钥时启用的 Mirror 酱 | `mirrorc`                                                |

列出镜像不保证可达、数据新鲜或对应通道一致。桌面同仓库/引用的镜像更新有祖先关系保护；Android 抓取后直接硬重置，没有这项保护。Android Git 对允许列表中的主机直接返回 `CertificateOk`，回调不检查证书，检测到系统 CA 目录也不能证明执行了证书链校验。Stable/dev 选择后端仓库/引用，两条主仓库分支目前均为 `master`，与游戏区服无关。

## Mirror 酱密钥

输入只修改本地草稿，点击**验证**或在框内 Enter，才按通道提交 `valid_cdk`。成功会存储密钥并可能显示有效期，失败会清空草稿/存储密钥与有效期；文本框不隐藏内容。

存储密钥后来源列表才提供 Mirror 酱。切换到其他来源会清空存储密钥和有效期，回来需再次验证。截图、问题反馈和共享设置中不要公开密钥。CDK 验证确认服务端密钥状态；桌面实现会解析响应的 `sha256`，但没有将其与下载的归档字节比较，验证成功不构成归档完整性证明。

明确选择元数据方式；测试全部会测列表中的方式，**不只测当前选项**，也不会自动选择最快项。结果展开/折叠与测试动作相互独立。

各行显示方式、等待/测试中/成功/错误、耗时秒数、缩写 SHA 及完整提示。桌面调用原生探测，WebUI 接收流式结果。界面期限为十秒，并忽略旧测试轮次的迟到结果；超时/错误不证明已安装后端是否正确，也不证明下载来源可用。

耗时只是一次网络观察，不是受控吞吐基准或适用于所有地点的排名；SHA 一致也不代表完整安装包已下载或验证。反馈时保留更新错误日志及来源/通道。

## 空闲自动更新

`idleAutoUpdate` 是默认开启的原生客户端全局设置，WebUI 没有。已知远端提交更新、连接和各配置快照就绪，且所有配置持续空闲时才协调后端更新。

空闲指没有当前任务和等待队列，持续调度器可能仍为运行状态；正在执行的一次性任务会排除。实现要求至少三秒稳定空闲，避免与客户端更新并发，失败后五分钟退避。

更新前将每档运行/停止状态及后端根目录可靠落盘，再停止任务；重启后同时恢复之前运行和**停止**的档。关闭开关阻止新的自动尝试，不取消已开始流程；已记录且合法的待恢复状态，即使开关关闭也可能继续恢复。恢复的是调度状态，不是把中断战斗精确接回某一帧。

Android 空闲路径会先发送 `stop_all_tasks` 并等待命令响应，再运行仓库同步，和手动入口不同。它同样调用上述延迟重启命令后重载 WebView，恢复记录不会让现有 Python 进程自动加载新代码。Android 终端中止会设置取消标志，但进行中的仓库同步没有消费该标志，终端显示停止后仍可能继续写文件。

## 更新之后

等待启动、身份连接和配置同步，核对本地后端提交/客户端版本，再验证设备及一个受监督任务，之后恢复无人值守。文件已变化或成功提示不证明新进程已经生效。

更新失败可能留下部分替换的代码：桌面新克隆逐项移入，Mirror 酱直接修改安装目录，Android git2 原地重置，启动归档也逐项替换。没有整目录原子交换或自动代码回滚；空闲恢复记录只保存调度状态。

Android 内嵌 Python/启动适配，bootstrap 可使用 APK 中存在的后端归档，缺少后端时也可下载；手动仓库更新走 git2。客户端不内置 Shizuku 安装器，也没有旧通知栏脚本开关；实际行为和游戏验证限制见 [Android 客户端](../guide/android)。仓库引用、禁用更新策略及高级来源配置见 [setup.toml](../reference/setup-toml)。
