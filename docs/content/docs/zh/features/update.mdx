打开**设置 → 更新**，后端代码与原生客户端是两种更新对象。检查成功不等于安装，检查失败也不代表已是最新；版本变更见[版本历史](../reference/release-history)。

## 版本组与动作

| 对象       | 展示和动作                                                    |
| ---------- | ------------------------------------------------------------- |
| 后端脚本   | 本地/最新提交缩为六位，完整详情在提示中；按所选通道/来源检查  |
| 原生客户端 | 当前/最新版本及检查、错误、可更新状态；可用更新时动作变为安装 |
| WebUI      | 可查看后端，没有原生客户端安装动作                            |

切换来源/通道后重新检查。空值、检查中、错误或禁用检查都不能证明版本相等；后端提交与客户端版本号也不能直接比较。

后端有更新时，侧栏脚本更新动作（或紧凑/悬浮入口）会停止全部任务。原生桌面随后重载，进入托管启动/更新流程；WebUI 使用后端流式更新，Android 使用自己的工作流和终端。它是真更新，不是再查元数据；操作前保留日志并导出必要配置。

原生客户端安装也会请求**停止全部任务**，等待停止状态，下载/安装后通常重启桌面应用。下载百分比不是整体安装/重启百分比；进度报错需排查，关闭进度视图不等于已提供取消机制。Android APK 安装按平台处理，不能照桌面重启流程解释。

## 来源与通道

以下属于共用后端设置，不是单档游戏策略：

| 字段           | 含义                                    |
| -------------- | --------------------------------------- |
| `updateMethod` | 后端下载/更新来源                       |
| `channel`      | `stable` 或 `dev`，解析为配置的仓库引用 |
| `shaMethod`    | 独立于下载来源的元数据/提交查询方式     |
| `mirrorcCdk`   | 已验证 Mirror 酱密钥，按敏感数据处理    |

当前客户端的来源选项为：

| 名称                               | 标识                                                     |
| ---------------------------------- | -------------------------------------------------------- |
| GitHub                             | `github`                                                 |
| CNB                                | `cnb`                                                    |
| Gitee                              | `gitee`                                                  |
| GitCode                            | `gitcode`                                                |
| GitHub v4、v6、CDN 加速            | `github_proxy_v4`、`github_proxy_v6`、`github_proxy_cdn` |
| gh-proxy.org                       | `gh_proxy`                                               |
| SevenCDN                           | `sevencdn`                                               |
| GitHubFast                         | `githubfast`                                             |
| BAAS CDN                           | `baas_cdn`                                               |
| 有已验证存储密钥时启用的 Mirror 酱 | `mirrorc`                                                |

列出镜像不保证可达、数据新鲜或对应通道一致。遇到过期镜像错误，不要盲目强制检出更旧代码。Stable/dev 是后端引用，不是游戏区服，也不是让你切换正在工作的 Git 分支。

## Mirror 酱密钥

输入只修改本地草稿，点击**验证**或在框内 Enter，才按通道提交 `valid_cdk`。成功会存储密钥并可能显示有效期，失败会清空草稿/存储密钥与有效期；文本框不隐藏内容。

存储密钥后来源列表才提供 Mirror 酱。切换到其他来源会清空存储密钥和有效期，回来需再次验证。截图、问题反馈和共享设置中不要公开密钥；此验证不是执行后端更新，也不是客户端许可证检查。

明确选择元数据方式；测试全部会测列表中的方式，**不只测当前选项**，也不会自动选择最快项。结果展开/折叠与测试动作相互独立。

各行显示方式、等待/测试中/成功/错误、耗时秒数、缩写 SHA 及完整提示。桌面调用原生探测，WebUI 接收流式结果。界面期限为十秒，并忽略旧测试轮次的迟到结果；超时/错误不证明已安装后端是否正确，也不证明下载来源可用。

耗时只是一次网络观察，不是受控吞吐基准或适用于所有地点的排名；SHA 一致也不代表完整安装包已下载或验证。反馈时保留更新错误日志及来源/通道。

## 空闲自动更新

`idleAutoUpdate` 是默认开启的原生客户端全局设置，WebUI 没有。已知远端提交更新、连接和各配置快照就绪，且所有配置持续空闲时才协调后端更新。

空闲指没有当前任务和等待队列，持续调度器可能仍为运行状态；正在执行的一次性任务会排除。实现要求至少三秒稳定空闲，避免与客户端更新并发，失败后五分钟退避。

更新前将每档运行/停止状态及后端根目录可靠落盘，再停止任务；重启后同时恢复之前运行和**停止**的档。关闭开关阻止新的自动尝试，不取消已开始流程；已记录且合法的待恢复状态，即使开关关闭也可能继续恢复。恢复的是调度状态，不是把中断战斗精确接回某一帧。

## 更新之后

等待启动、身份连接和配置同步，核对本地后端提交/客户端版本，再验证设备及一个受监督任务，之后恢复无人值守。文件已变化或成功提示不证明新进程已经生效。

Android 内嵌 Python/启动适配，但后端另行下载，不内置 Shizuku 安装器，也没有旧通知栏脚本开关；实际行为和游戏验证限制见 [Android 客户端](../guide/android)。仓库引用、禁用更新策略及高级来源配置见 [setup.toml](../reference/setup-toml)。
