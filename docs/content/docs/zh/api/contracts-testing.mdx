API 改动完成前，必须确认配置契约、注入边界和脚本验证都成立。只让桌面 dev server 跑起来不足以证明 Android 版可用。

## 配置契约

| 配置 | 位置 | 规则 |
| --- | --- | --- |
| app storage | Tauri app data 或 Android app storage | 保存启动状态、安装路径、认证状态和 updater 配置。 |
| `setup.toml` | 后端根目录或 Android storage | 保存 main sha、更新源、运行时配置。 |
| profile config | 后端配置目录 | 由 sync 通道推送快照和 patch。 |
| `screenshot_method` | 脚本配置 | Android 必须固定为 `android_local`。 |
| `control_method` | 脚本配置 | Android 必须固定为 `android_local`。 |

新增字段必须给出默认值和迁移策略。前端不能依赖“字段一定存在”，后端不能依赖“前端一定会先写入新字段”。

## Service 注入边界

Service 模式的目标是隔离注入：

| 允许 | 不允许 |
| --- | --- |
| 在 `service` 文件夹内部定义注入函数。 | 为 service 模式改 `core`、`module`、`main` 的主流程。 |
| Android runtime 包装 `service.injection.apply_service_injections`。 | Android runtime 直接 monkey patch 分散在主仓库各处。 |
| 通过稳定 WebSocket/HTTP API 影响前端。 | 让前端依赖 service 内部实现细节。 |
| 在 workflow 或 deploy 脚本里做打包适配。 | 把打包适配混进运行时 API。 |

如果确实需要修改主仓库行为，应先把能力抽象成主仓库通用扩展点，再由 service 注入使用；不要为了 service 模式写一次性分支。

## 最低验证矩阵

| 范围 | 命令或操作 | 通过标准 |
| --- | --- | --- |
| 前端 | `bun run lint` | 无 lint 错误。 |
| Tauri 构建 | `bun run build:tauri` | Web build 和 Rust 构建通过。 |
| Rust workspace | `cargo check --workspace` | 所有 crate 类型检查通过。 |
| Python | `python -m py_compile ...` 或 `python -m compileall -q ...` | 可运行文件无语法错误。 |
| Android debug | `bun scripts/android-build-debug.mjs --skip-web-build --abi x86_64` | APK debug 构建通过。 |
| Android 模拟器 | 安装、启动、截图确认、低风险脚本运行 | UI 可操作，后端连接，控制模式固定，日志正常。 |
| 文档站 | `bun run build` | Fumadocs 静态导出通过。 |

Windows 上某些 test binary 可能因为 error 740 需要提升权限执行。遇到这种情况应记录具体二进制和错误，不要把它混同为编译失败。

## API 变更检查表

1. 是否更新了中英文文档。
2. 是否明确桌面端和 Android 端行为差异。
3. 是否保留 WebSocket frame 向后兼容。
4. 是否避免 service 模式修改 `service` 文件夹外运行时代码。
5. 是否跑过对应脚本并记录不可运行原因。
