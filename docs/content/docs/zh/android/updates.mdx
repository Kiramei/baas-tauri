title: 更新与排查
---

后端更新使用应用配置的来源，并显示进度和输出；失败时保留启动、系统及更新日志。下载请求失败、身份验证失败、游戏识别失败属于不同层，调截图间隔不能修复下载。

Android 手动后端更新入口不会等待所有任务停止。更新前先核对各配置档的运行状态并停止任务。当前更新命令会延后服务重启；磁盘同步成功、WebView 重载和新 Python 代码生效需要分别确认。同步成功后，如需重新启动后端进程，先停止全部任务、关闭后台游戏显示，再到 Android 系统设置的应用信息中**强行停止 BAAS**，重新打开并核对后端版本、日志及有监督的运行结果。返回键或划掉界面可能保留服务进程。部分服务文件仍由 APK 匹配覆盖层提供，仅更新后端仓库不会替换这些文件。[更新器内部机制](../reference/updater-internals)说明具体流程和限制。

| 现象               | 核对项目                                               |
| ------------------ | ------------------------------------------------------ |
| APK 无法安装       | 真实 CPU ABI、Android 版本、可信安装权限、已有包和签名 |
| 准备失败           | 对应阶段终端、网络/来源、应用私有存储                  |
| 游戏未安装提示     | 当前配置档精确对应的地区包名                           |
| Shizuku 不可用     | 安装、运行、授权三个独立状态                           |
| 黑屏、画面未更新或旧版 Live 停在启动图 | 实际游戏任务与显示归属、修复构建、原生采集错误和 ABI 兼容 |
| OCR 初始化失败 | 看具体动态库/模型错误；界面已经连接不代表 OCR 就绪 |
| 后端断连           | 服务/进程日志及后台限制，不仅看通知是否显示            |

## 与电脑端 uiautomator2 共用设备

Android BAAS 的本机设备桥接监听**设备自身**的 `127.0.0.1:7912`，`/version` 返回 `baas-shizuku-display-1`。它供内嵌运行时使用，受私有令牌保护，接口也与标准 atx-agent 不同。电脑端普通 uiautomator2 经 ADB 转发访问同一端口时，可能收到 HTTP 403，继而报 `PIL.Image.open` 无法识别图片。

这类错误先检查端口对应的服务。不要关闭桥接认证或把应用私有令牌填入普通 atx-agent 客户端。需要切换到电脑端 uiautomator2 时，先停止任务，再通过系统应用信息停止 Android BAAS 的进程，确认原监听释放后准备标准 atx-agent；仅把界面切到后台不会停止其服务。反向切回 Android BAAS 前，同样处理另一服务的端口占用。停止进程会中断该客户端当前的后台任务。
