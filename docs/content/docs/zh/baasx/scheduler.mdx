BAASX 将任务配置、日常调度和运行控制分开：先在[配置](./configuration)中确定任务怎样执行，再决定运行一项任务，还是启动当前配置档的日常调度。

终端示意用于说明选择、调度和日志控件。实际任务、队列与结果来自所连接的后端。

## 选对运行入口

| 工作台命令       | 作用                                   | 确认与范围                                     |
| ---------------- | -------------------------------------- | ---------------------------------------------- |
| `/tasks`         | 打开日常任务列表                       | 选中一项后只提交这项任务，并要求确认           |
| `/oneoff`        | 打开推图、剧情和活动的一次性任务列表   | 选择后单次执行，不加入日常调度                 |
| `/run <task-id>` | 用后端任务 ID 提交一项任务             | 默认要求确认；不带 ID 的 `/run` 打开任务列表   |
| `/start`         | 启动当前配置档已有的日常调度           | 直接执行，无需再次确认；运行范围由调度规则决定 |
| `/stop`          | 请求停止当前配置档正在运行的任务或调度 | 默认要求确认；用状态和日志确认已停止           |
| `/scheduler`     | 编辑当前配置档的日常调度规则           | 保存规则本身不会发送启动命令                   |

`/start` 已经是明确的启动动作。无需再按一次 Yes，也无需为它添加 `--yes`。单次任务、停止操作和指令包中的修改步骤仍保留各自的确认流程。

## 运行一项任务

1. 用 `/profiles` 选择目标配置档，确认总览中的名称正确。
2. 在 `/config` 核对该任务的配置，例如设备地址、学生偏好、购买项目或次数。
3. 输入 `/tasks`，选择一个已有任务；或者输入 `/run` 加上其真实 ID。
4. 在确认窗口核对配置档和任务，Enter 提交；`n` 或 Esc 取消。
5. 观察实时状态与日志，直到后端报告结束。提交被接受和执行完成是两个状态。

例如，当前任务列表确实有 `mail` 时，可以输入：

```text
/run mail
```

任务列表可用显示名称或 ID 筛选。语言切换会改变名称，不会改变提交给后端的任务 ID。任意未知名称不会作为任务执行；已有运行时也不会重复启动同一配置档的新运行。

## 普通、困难、剧情与活动的一次性任务

在 `/tasks` 顶部切换“一次性任务”，或直接输入 `/oneoff`。这些入口与桌面推图页面的单独执行操作对应：

| 用途         | 可直接输入的命令                        |
| ------------ | --------------------------------------- |
| 普通关卡推图 | `/run start_normal_task`                |
| 困难关卡推图 | `/run start_hard_task`                  |
| 主线剧情     | `/run start_main_story`                 |
| 社团剧情     | `/run start_group_story`                |
| 小故事       | `/run start_mini_story`                 |
| 活动剧情     | `/run start_explore_activity_story`     |
| 活动任务     | `/run start_explore_activity_mission`   |
| 活动挑战     | `/run start_explore_activity_challenge` |

执行前先在配置中检查推图计划、编队和相关活动设置。出现入口只表示 BAASX 支持提交该后端动作，关卡解锁、当前活动和设备状态仍由游戏与后端决定。

这些动作不会自动成为 `/start` 的日常任务，也不会因在一次性列表中选择过而加入下次调度。退出一次性列表可按 Esc 返回日常任务列表。

## 启动和停止日常调度

推荐先检查规则，再启动：

```text
/scheduler
/start
/logs
```

上面是分别输入的工作台命令。查看 `/scheduler` 后完成必要修改，再输入 `/start`。后端根据启用状态、下次时间、优先级、间隔、每日重置和前后置关系决定执行安排。

需要停止时输入：

```text
/stop
```

修改启用开关、执行时间或优先级不会直接中断当前正在执行的任务。需要先停止当前运行再改安排时，提交 `/stop` 并等待后端状态更新，然后编辑。

总览显示当前任务、等待队列、启用数量和下次安排。下次时间是调度资格的一部分；当前任务、队列和任务条件都会影响真实启动时刻，不能据此保证精确到秒的执行时间。

## 编辑调度字段

进入 `/scheduler`，选择任务，再选择要修改的字段。数字或单值编辑通常用 Enter 保存；时间行和任务列表用 Ctrl+S。单元格编辑先回到当前字段草稿，再提交整个字段。默认会出现修改确认。

| 字段                           | 含义                 | 输入与限制                                                         |
| ------------------------------ | -------------------- | ------------------------------------------------------------------ |
| 启用 `enabled`                 | 是否参加日常调度     | 开关                                                               |
| 下次执行时间 `next_tick`       | 下一次可执行的时间   | 本地日期时间、带时区的 ISO 日期、Unix 秒、`now`；`立即` 保存为 `0` |
| 优先级 `priority`              | 调度顺序参数         | 整数，数值越小越优先                                               |
| 执行间隔 `interval`            | 执行间隔             | 非负整数秒；`0` 使用每日重置时间                                   |
| 每日重置 `daily_reset`         | 一天中的重置时刻     | 时间行，每行包含时、分、秒                                         |
| 禁用时段 `disabled_time_range` | 暂不执行的时间范围   | 每行一个开始和结束时间；结束不能早于开始                           |
| 前置任务 `pre_task`            | 按顺序执行的前置任务 | 从其他已有任务中选择并排序                                         |
| 后置任务 `post_task`           | 按顺序执行的后置任务 | 从其他已有任务中选择并排序                                         |

### 时间输入

“下次执行时间”可使用以下形式：

| 示例                        | 解释                          |
| --------------------------- | ----------------------------- |
| `now`                       | 保存当前时间的 Unix 秒值      |
| `立即`                      | 保存立即可执行标记 `0`        |
| `2027-01-15 05:30:00`       | 按运行 BAASX 的本地时区解析   |
| `2027-01-15T05:30:00+08:00` | 使用明确的时区偏移            |
| `1800000000`                | Unix 秒值示例；不要输入毫秒值 |

以上日期只是格式示例，不是推荐的执行时间。界面将已保存的时间显示为本地日期时间。

每日重置使用结构化时间行：小时范围 `0–23`，分和秒范围 `0–59`。例如添加两行 `05:00:00` 和 `17:00:00`，分别表示两个重置时刻。`+` 添加时间行，Backspace/Delete 移除选中的行，Ctrl+S 保存这个字段。

跨午夜的禁用时段需要拆成两行。例如禁止 `23:30` 到次日 `06:00`：

| 行  | 开始       | 结束       |
| --- | ---------- | ---------- |
| 1   | `23:30:00` | `23:59:59` |
| 2   | `00:00:00` | `06:00:00` |

日常规则最终由后端调度器解释。使用远程后端时，应同时核对服务所在环境的时间设置。

### 前置与后置任务

前后置任务使用有序选择器。↑/↓ 选择，←/→ 上下移动，Space 添加或移除，Ctrl+S 保存。任务不能引用自己，同一列表不能重复引用一个任务，不能填写不存在的任务 ID。

这些字段保存后端任务关系；列表中的名称是标签，实际保存的是函数 ID。BAASX 的终端调度页使用字段和列表编辑，不提供桌面的图形工作流画布。

## 批量操作与新增任务状态

调度列表顶部有整档操作：

| 操作             | 影响                                          |
| ---------------- | --------------------------------------------- |
| 全部启用/禁用    | 有未启用任务时启用全部；全部已启用时禁用全部  |
| 重置执行时间     | 把全部任务的下次执行时间设为当前时间          |
| 新增任务默认状态 | `on` 启用、`off` 禁用、`default` 使用后端默认 |

批量操作针对整个配置档的调度列表，包括被当前搜索隐藏的任务。重置执行时间会改变任务何时具备执行资格；它不是清理日志，也不负责启动调度。

调度保存只提交实际改变的字段，并检查读取时的字段基线。检测到并发变更时会拒绝覆盖。取消或保存失败后草稿保留；需要采用其他客户端的新值时，退出编辑并重新打开 `/scheduler` 读取，再修改。

## 实时日志与状态

运行任务后，工作台自动展示日志。宽度至少 110 列时可使用右侧分栏；拖动中间竖线调整左右宽度，终端缩放会保留比例。窄屏使用独立日志页。

- `/logs` 打开实时日志，Ctrl+L 也可进入。
- 滚轮或 PageUp/PageDown 查看历史；向上滚动暂停跟随，回到底部恢复。
- `/logs 50` 读取最近 50 条日志并显示结果。
- `/status` 读取运行状态。结合当前任务、运行编号和退出码判断结果。
- `/reload` 或 Ctrl+R 重载工作台界面；后台运行继续，未保存编辑会清除。

日志保留有界，不应当作永久审计存档。需要持续采集时可使用下方的脚本命令，将输出交给自己的日志工具。

## 在系统终端等待结果

下面的命令运行在系统终端中，**没有前导 `/`**。`wait`、`watch` 和 `--follow` 属于非交互 CLI；它们不是工作台中的 `/wait`、`/watch` 命令。

先连接并配置已有服务的认证信息，将 `my-profile` 换成实际配置档。以下示例明确连接外部服务：

```bash
# 单次运行并等待结束，同时跟随日志
baasx --server ws://127.0.0.1:8190 --profile my-profile \
  --yes --wait --follow run start_normal_task

# 等待先前返回的运行编号；把 RUN_ID 换成真实 run_id
baasx --server ws://127.0.0.1:8190 --profile my-profile \
  --wait-timeout 120 wait RUN_ID

# 持续观察状态，或从最近 50 条开始持续跟随日志
baasx --server ws://127.0.0.1:8190 --profile my-profile watch
baasx --server ws://127.0.0.1:8190 --profile my-profile --follow logs 50
```

外部服务上的 `run` / `start` 默认只返回是否接受提交，以及可用的 `run_id`；`completed: false` 不是失败，也不是完成。`--wait` 等待同一运行编号结束，`--follow` 同时显示相关日志并等待任务结束。执行成功以终态和退出码为依据；无法证明完成时不会报告成功。

`--wait-timeout` 单位为秒，范围 `1–86400`。外部服务默认等待上限为 300 秒，超时退出码为 `124`。支持 `--json` 时可输出机器可读结果，持续监控会逐条输出 JSON 事件。

### 等待取消与后端生命周期

| 连接方式                           | 关闭 CLI 或取消等待后的行为                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| `--server` / `--pipe` 连接已有服务 | CLI 退出或停止监控，已提交到外部服务的任务继续；停止任务需显式发送 `stop`     |
| CLI 托管的本地环境                 | 本次 CLI 退出会清理自己启动的后端和子进程；取消本地等待或等待超时也会触发清理 |

托管本地模式的一次性脚本会自动等待它发起的 `run`、`start` 或指令包运行，默认最多 24 小时，可用 `--wait-timeout` 覆盖。需要服务长期常驻时，应先独立启动服务，再用 `--server` 或 `--pipe` 连接。

`--read-only` 阻止启动、停止和修改等动作；`--dry-run` 预览修改而不提交。可以先用 `baasx --profile my-profile --dry-run start` 核对目标，再决定实际运行。
