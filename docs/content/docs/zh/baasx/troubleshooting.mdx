---
title: 故障排查
description: 从启动、连接、配置、任务完成和指令包入手排查 BAASX，保留配置并区分本地与外部服务。
---

排查时先记录命令、配置档 ID、错误原文和发生时间，再选择对应的问题处理。不要把“程序能打开”“健康检查通过”或“启动已接受”当作真实游戏任务完成。

## 先收集最小信息

```bash
baasx --version
baasx --json settings show
baasx --json doctor
baasx --json profiles
baasx --profile PROFILE_ID --json status
baasx --profile PROFILE_ID --json logs 30
```

`settings show` 同时显示保存值和环境/参数覆盖后的有效值。`doctor` 在 WebSocket 模式检查服务健康，在管道或托管本地模式会尝试连接。`status` 与日志更适合判断任务实际状态。

顶部仅显示配置档与连接状态，不显示 socket 路径；看不到路径不表示没有连接。需要排查地址时查看 `settings show` 或 `doctor`。提交问题时去掉登录 Key、推送凭据、私人路径、设备地址等无关信息；只分享足以复现的片段。

## 打不开工作台，或提示必须指定命令

工作台需要交互终端、没有位置命令，并且没有启用 `--json`。下面两条的用途不同：

```bash
baasx --demo
baasx --demo --json status
```

前者打开工作台，后者输出一个 JSON 结果后退出。IDE 的“输出”面板、重定向 stdin 或管道不一定是 TTY；改在真正的终端中运行。不要把一串 `/tasks` 文本管道给程序，它不会被解释成交互按键。

如果无参数启动立即报 JSON/指令包错误，先跳到[指令包加载失败](#指令包加载失败)或[本地偏好损坏](#本地偏好损坏)，不要先删除整个配置目录。

## 本地运行环境安装或启动失败

BAASX 本地模式需要提供 `main.service.py` 和本地管道协议的 BAAS 服务版。当前向导使用 `dev` 通道，旧 GUI `stable` 后端不是可替代的服务版；`stable` 被提前拒绝是预期行为。

- 从完整发行归档解压，保留可执行文件与 `runtime/` 的相对位置及执行权限。不要只复制一个二进制后删除安装组件。
- Bun 包也要保留随包提供的运行组件。用户使用已打包归档不需要 Rust；从源码开发才需要 Rust、Cargo 和本机编译工具链。
- 当前本地 OCR 预构建针对 Windows x64、Linux x64、macOS ARM64。不要把不同系统/架构的组件混在同一归档中使用。
- 在安装步骤面板展开失败步骤，检查下载、Python、依赖和后端握手的具体日志。Esc 可以取消正在进行的安装或更新；修正原因后从向导重试。
- `/local` 用于启动已有完整环境，不等于补全任意损坏的手工目录。先检查向导报告，再决定是否需要重新安装。

正式连接成功后会自动进入总览。若仍停在失败进度，先查看错误；只有明确已连接且无正在进行的前台操作时，再尝试 `/reload`。该命令重建界面，不重装环境，也不重启正在工作的后端。

## 无法连接 WebSocket 或本地管道

1. 确认服务进程已启动，地址、端口或管道路径来自该服务。
2. 查看 `settings show` 的 `effective`，检查是否被 `BAAS_SERVER`、`BAAS_PIPE`、`--server` 或 `--pipe` 覆盖。
3. WebSocket 脚本提供 `BAAS_KEY`；交互模式可隐藏输入。不能把 Key 放入 URL 查询参数。
4. 签名公钥不匹配时，核对服务实际公钥；自部署使用不同公钥须明确配置 `--server-key` 或 `BAAS_SERVER_SIGN_PUBLIC_KEY`。反复更换登录 Key 不能修复签名公钥问题。
5. Unix socket 需要当前用户有权访问；旧 socket 文件本身不证明服务仍在监听。Windows 要使用后端实际提供的命名管道。

```bash
baasx --server ws://127.0.0.1:8190 --json doctor
baasx --server ws://127.0.0.1:8190 --json profiles
```

第一条通过但第二条失败，仍可能是认证或业务通道问题。查看第二条的具体错误；`doctor` 的 HTTP 健康结果不能替代认证测试。`--timeout` 单位是毫秒，允许 100–300000；它和任务等待的秒数不是同一参数。

## 配置档、任务或设置找不到

先运行 `profiles`，再用精确 ID 选择。名称重复时不要依赖名称匹配。

```bash
baasx profiles
baasx --profile PROFILE_ID tasks
baasx --profile PROFILE_ID config get
```

- `tasks` 是日常调度目录，不包含推图和活动等一次性入口。工作台用 `/oneoff`，脚本用[支持的一次性任务 ID](./cli#一次性任务-id)。
- 任务显示名称不一定是 `run` 使用的 ID。把返回对象的键名传给 `run`；一次性任务使用完整的 `start_...` ID。
- `/config` 仅显示当前后端提供且允许编辑的字段。条件字段可能取决于咖啡厅数量、邀请模式、制造阶段、模拟器模式等设置。
- 配置分类里的“日程”是区域次数和等级偏好；顶部“调度”是任务执行时间和顺序，两者不是同一页。
- 学生、物品或区域名来自后端静态目录。目录未就绪时不要凭空填写 ID；先检查连接和后端资源，再重新进入配置或执行 `/reload`。
- 服务器类型只读。内部缓存、资产计数和未开放字段即使能在读取结果中看见，也不能通过 `config set` 强行修改。

## 配置保存失败或冲突

数字必须满足该字段的范围和整数要求，选项要使用真实值。终端命令中的配置值必须是 JSON：

```bash
baasx --profile PROFILE_ID --dry-run config set /cafe_reward_affection_pat_round 5
baasx --profile PROFILE_ID --dry-run config set /screenshot_method '"adb"'
```

出现版本或字段冲突通常意味着另一客户端在读取后修改了同一字段。重新读取当前值并比较，再提交新的修改；BAASX 不会自动覆盖并发变更。取消或验证失败时编辑器保留草稿，但 `/reload` 会清除未保存草稿。

`[REDACTED]` 等脱敏占位符不是原始秘密值，不能复制回配置。需要修改凭据时输入新值。正常的只读读取也可能包含敏感配置，分享 JSON 前应只保留相关字段。

## “启动成功”后任务没有完成

外部服务上的 `run` / `start` 默认只确认请求被接受，`completed: false` 是正常的异步结果。检查当前状态，或等待相同运行：

```bash
baasx --profile PROFILE_ID --json status
baasx --profile PROFILE_ID --json logs 50
baasx --profile PROFILE_ID --wait-timeout 600 --json wait RUN_ID
```

将 `RUN_ID` 替换成启动结果中的编号。`succeeded: true` 才表示观察到成功退出；`null` 表示没有充分的成功证据。`already-running` 表示已有运行，CLI 没有再提交一次。先查看当前任务，确实需要停止时明确执行 `stop`，不要靠重复 `run` 试图覆盖。

如果提示运行被替换或编号不匹配，原编号和当前任务已经不是同一次执行。重新读取状态和日志，不能把后来的一次成功当作前一次成功。

## 等待超时、断线与退出

`--wait-timeout` 单位为秒，允许 1–86400；超时退出码为 `124`。`--timeout` 是连接/请求毫秒超时。两个参数不能互换。

| 连接方式                       | 取消等待或关闭 CLI 后                              |
| ------------------------------ | -------------------------------------------------- |
| CLI 自己启动的本地后端         | 清理该后端及其子进程，当前任务不在该后端继续执行   |
| `--server` / `--pipe` 外部服务 | 服务和已提交的任务可以继续运行；重新连接后读取状态 |
| 工作台 `/reload`               | CLI 未退出，原本地后端和后台任务保留               |

网络恢复会重建连接和读取状态，不会自动重放修改。如果提交时断线，先查状态与日志再决定后续操作。长期后台执行应采用独立服务，不要依赖即将关闭的私有本地后端。

## 指令包加载失败

错误一般包含文件路径和 JSON 字段位置。常见原因：

- JSON 含注释、尾逗号或未配对引号。
- `version` 写成 `"1"`；它必须是数字 `1`。
- 包 ID 或命令名重复，或命令名覆盖 `run`、`reload`、`daily` 等已有命令。
- 缺少必填 `args: {}`，使用未允许的动作或额外字段。
- 把桌面插件 ZIP、JavaScript、Shell 命令或嵌套文件夹当成指令包。

先修复出错文件，或移到包目录之外。也可把 `.json` 改成 `.json.disabled`，保留内容以便修复。然后执行：

```bash
baasx --json packs
baasx --json reload
```

这两条单次 CLI 不会刷新另一个工作台。工作台需要自己执行 `/reload`。重载检查失败时保留旧内容，因此旧命令仍在列表里不代表新文件已被接受。结构和参数约束见[指令包格式](./command-packs#json-结构与限制)。

## 更新被拒绝或环境被占用

应用本地更新前，程序会检查其托管后端的全部配置档是否空闲；任务、调度或等待队列仍存在时会拒绝更新。先读状态，停止需要停止的运行，等后端确认空闲后再重试。

```bash
baasx --json check-update
baasx --dry-run --json update
baasx --yes update
```

其他 CLI 实例持有同一环境的运行租约时也可能阻止替换。关闭确实已经不再使用该环境的实例，不要手工删除锁文件来绕过正在运行的进程。更新只作用于 CLI 托管的完整 `dev` 环境，不会升级或关闭通过 `--server` / `--pipe` 连接的外部服务。

## 显示、鼠标或快捷键异常

- 最小支持窗口是 24×12；更小会提示放大。窄屏折叠页头和列表，不会显示与宽屏相同的行数。
- 鼠标交互依赖终端传递鼠标报告；终端或复用器截获事件时先使用键盘验证：↑↓ 选择、Enter 打开、Esc 返回、Shift+Tab 切页。
- 终端至少 110 列时支持工作区和日志左右分栏，拖动竖线调宽度；窄屏使用独立日志页。
- 日志上滚后暂停自动跟随，回到底部恢复。日志页或帮助可用 PageUp/PageDown 翻页。
- 动画或颜色不适合当前终端时使用 `BAAS_REDUCED_MOTION=1` 或 `--no-color`。只影响显示，不改变任务执行。
- `/reload` / Ctrl+R 可重建界面；不要在有需要保留的未保存草稿时使用。它不会将正在运行的可执行文件替换为磁盘上的新版本。

## 本地偏好损坏

启动错误可能来自 `settings.json` 的 JSON 语法、字段类型或服务地址。先备份该文件，再修正错误；不要删除包含运行环境和自定义包的整个目录。登录 Key 不应被添加到此文件。

若原配置使排查命令也无法启动，可用独立目录确认程序本身能运行：

```bash
baasx --config-home ./baasx-diagnostic --demo --json profiles
```

该命令使用新的演示进程，不读取原配置档或真实设备，也不证明原后端健康。确认程序可运行后，回到原目录检查偏好和包。问题仍无法解决时，提供版本、系统/架构、连接方式、已脱敏的命令与错误，以及问题出现在启动、连接、提交还是等待阶段。
