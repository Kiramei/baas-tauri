BAASX 的配置页决定任务**怎样执行**，例如邀请哪些学生、每个日程区域执行几次、购买哪些商品。任务是否参加日常运行、何时运行，另在[调度](./scheduler)设置。

终端编辑器使用显式保存：单值通常按 Enter，列表和表格按 Ctrl+S，再按提示确认提交。打开字段或改变本地草稿不会自动写入后端。

## 选择配置档并找到字段

1. 输入 `/profiles`，选择要修改的配置档。也可用 `/use my-profile`，其中 `my-profile` 替换成实际 ID 或唯一名称。
2. 输入 `/config` 打开配置分类。尚未选配置档时，工作台会先引导选择，再回到配置页。
3. 使用 ↑/↓ 和 Enter，或鼠标点击，进入分类和字段。
4. 在列表的输入框中直接输入字段名称或键名筛选，例如 `createPriority_phase1`、`lesson_times`。以 `/` 开头会进入命令搜索；搜索配置键时不必输入前导斜杠。
5. 清空输入恢复列表；Esc 从字段返回分类，再返回上一级。

| 分类                                   | 常见设置                                   |
| -------------------------------------- | ------------------------------------------ |
| 咖啡厅                                 | 收取奖励、邀请条件、学生偏好、互动方式     |
| 日程                                   | 收藏学生、好感度优先、各区域次数和等级偏好 |
| 商店                                   | 普通商店、战术对抗赛商店的商品与刷新次数   |
| 制造                                   | 制造次数、阶段、材料规则和各阶段优先级     |
| 竞技场、总力战、制约解除决战、战术测试 | 对应战斗任务的条件、难度或编队规则         |
| 日常扫荡                               | 普通/困难计划、各类次数、活动与购票        |
| 好友清理                               | 白名单和清理阈值                           |
| 服务器、脚本、模拟器                   | 后端提供的连接、执行和模拟器设置           |
| 推图、编队、推送                       | 推图计划、队伍属性及通知渠道               |

仅显示后端实际提供且允许编辑的字段。部分选项有前提：例如按姓名邀请时才显示对应学生列表，启用收藏学生后才显示日程学生偏好，制造阶段数决定后续阶段是否出现。服务器类型保持只读；内部缓存和资产计数不会成为可任意修改的 JSON 字段。

学生、物品和关卡名称来自后端目录。切换界面语言只改变显示文案，保存的枚举值仍按后端要求发送。

## 编辑和保存的基本操作

| 编辑器           | 修改方法                                          | 保存                |
| ---------------- | ------------------------------------------------- | ------------------- |
| 开关             | Space 切换；←/→ 关闭或开启                        | Enter 或 Ctrl+S     |
| 单选             | ↑/↓ 选择选项                                      | Enter 或 Ctrl+S     |
| 数字、文本       | 直接输入替换原值；Ctrl+A 清空后重新输入           | Enter 或 Ctrl+S     |
| 多选、优先级列表 | 选择、添加、移除或调整顺序                        | Ctrl+S 保存整个字段 |
| 普通行列表       | Enter 打开行和列；`+` 加行，Backspace/Delete 删行 | Ctrl+S 保存整个字段 |
| 日程表格         | ↑/↓ 选区域，←/→ 选列；Enter 编辑单元格            | Ctrl+S 保存整张表   |

数字字段检查整数要求和上下限。临时留空、超范围或格式不正确时会显示错误，草稿保留供修正。

编辑表格或复合行时，**子编辑器的保存先更新本地草稿**。例如输入一个次数并按 Enter 后，会回到表格；还需 Ctrl+S 才提交整张表。单元格内按 Esc 只放弃该单元格尚未应用的修改，表格中此前已经完成的草稿修改仍保留；从表格退出则放弃本次表格草稿。

提交确认默认选中 Yes。Enter 确认，`n` 或方向键切换取消，也可点击按钮。等待出现保存成功反馈；仅回到列表或关闭确认窗口不能当作成功证明。

## 调整制造和学生优先级

制造优先级、咖啡厅学生偏好、日程收藏学生等有序列表按当前保存顺序显示，并标出 `1.`、`2.`、`3.`。靠上的项目优先，未选择的候选项排在已选列表之后。

1. 打开要调整的字段，例如制造中的第一阶段优先级。
2. 用 ↑/↓ 或鼠标点击选中一个条目。点击名称只选择，不会取消该条目。
3. 按 ← 上移、→ 下移，或点击底部“上移”“下移”。`<` / `>` 也可调整顺序。
4. Space、行尾 `+`/`−` 或底部“添加”“移除”改变选择。新加入的条目排在已选列表末尾。
5. 按 `/` 搜索名称，输入关键词后按 Enter 结束搜索输入。Esc 先清除搜索，再按 Esc 才退出编辑器。
6. 核对编号并按 Ctrl+S 保存，在确认窗口提交。

搜索只是筛选可见条目，不改变优先级。移动时仍按完整已选列表的顺序调整，筛选隐藏的相邻项也可能与当前项交换位置。

旧配置中已保存但目录暂时没有的条目可继续显示、保留或移除；不能把一个不可用选项当作新候选项添加。若某类学生列表没有出现，先核对邀请方式、收藏开关及当前区服。

## 日程：每个区域都有次数

进入 **配置 → 日程**。区域设置分成两张表：

| 表格              | 内容                           | 对应字段                             |
| ----------------- | ------------------------------ | ------------------------------------ |
| 日程次数          | 每个区域的执行次数             | `lesson_times`                       |
| 日程区域 · 优先级 | 每个区域的等级选择与已保存顺序 | `lesson_each_region_object_priority` |

表格按后端当前区服的完整区域目录生成。旧配置数组较短时，缺少的区域也会出现：新区域次数默认为 `1`，等级默认包含全部四种。原有的 `0` 次、空等级选择和已存顺序会保留；已有数组比目录更长时，额外行也不会被悄悄删除。仅打开表格不会把这些默认值写回。

### 修改某个区域次数

1. 打开“日程次数”，选择目标区域。
2. 点击 `[-]` / `[+]`，或按 `-` / `+`，逐次调整。
3. 要直接输入，按 Enter 打开该次数，输入数值，再按 Enter 回到表格草稿。
4. 检查其他区域，按 Ctrl+S 保存整表并确认。

次数范围是整数 `0–99`。`0` 给该区域的普通区域处理分配零次；次数是本次任务请求的数量，不是历史完成计数。学生优先规则和可用票券也会影响实际执行，结果应以日志为准。

### 修改区域等级

在等级表中点击单元格或按 Enter，进入该区域的优先级编辑器。选择、移除或移动等级后，Ctrl+S 回到表格草稿，再 Ctrl+S 提交整张表。界面保留所选顺序；后端的好感度优先和选点规则决定实际选择结果。需要跳过一个区域时使用次数 `0`，不要把“等级列表为空”当作关闭开关。

日程券购买次数位于日常扫荡的购票设置中。表格补齐区域只补配置，不增加票券。

## 商店：先选商店，再选商品

进入 **配置 → 商店**，先选择普通商店或战术对抗赛商店，再编辑该店的刷新次数和商品。这样两家店的商品不会混成一个列表。

- 每家店保留自己的刷新次数与商品选择。
- 商品名称来自当前区服目录，商品开关按其对应的后端位置保存。
- 从配置搜索直接找到商品并打开后，工作台会进入它所属的商店；退出字段后仍留在这家店。
- Esc 依次返回商品列表、商店选择、配置分类。

设置商品或刷新次数只保存购买规则。实际购买在对应任务运行时发生，刷新与商品消耗按游戏及后端规则计算。

## 次数、全部与最大模式

**无需输入 `∞`。** 有上限的数字按范围输入；支持“全部”或“最大”的字段，通过模式或选项选择器设置。它们按可用体力、票券和游戏上限计算实际数量。

| 设置                     | 可用模式                                   | 需要核对                                                      |
| ------------------------ | ------------------------------------------ | ------------------------------------------------------------- |
| 普通/困难扫荡计划        | 固定次数；支持时可选最多 `max`             | 普通关卡编号 `1–5`、困难 `1–3`；国服/B 服困难计划不提供 `max` |
| 悬赏、学园交流、特别委托 | 跳过、固定次数、全部可用                   | 固定次数为非负整数；全部保存为 `max`                          |
| 活动扫荡                 | 跳过、固定次数、体力占比、全部已选活动关卡 | 占比输入 `0–100`；“全部”活动模式要求次数列表只有一项          |
| 购买票券                 | 跳过、固定购买次数、最大购买次数           | 这是购买上限；悬赏 `1–12`、日程券 `1–4`、学园交流 `1–12`      |

活动的“体力占比”输入百分比：输入 `50` 表示 50%，序列化为 `0.5`；输入 `100` 序列化为 `1.0`。固定次数 `1` 保存为 `1`，含义是扫荡一次。通过模式控件区分这两种含义即可。

活动“全部”使用独立的后端表示 `-1`，普通扫荡“最大”使用 `max`。它们不是可互换的文本输入。活动关卡、资源消耗和实际次数仍由当前后端活动数据决定。

## 用命令读取和修改

以下是工作台输入框中的命令。先选配置档，再读取实际字段：

```text
/config get /lesson_times
/config get /createPriority_phase1
/config get /cafe_reward_affection_pat_round
/config set /cafe_reward_affection_pat_round 3
```

`config set` 的值必须是 JSON。数字用 `3`，布尔值用 `true` / `false`；字符串需要保留 JSON 双引号。它与界面编辑器使用相同的字段白名单、条件和校验规则，不能借此修改内部缓存或只读服务器类型。

在系统终端运行时，命令没有前导 `/`，并明确指定配置档：

```bash
baasx --profile my-profile config get /cafe_reward_affection_pat_round
baasx --profile my-profile --dry-run config set /cafe_reward_affection_pat_round 3
baasx --profile my-profile --yes config set /cafe_reward_affection_pat_round 3
```

`--dry-run` 预览修改，`--yes` 用于明确执行非交互修改。`my-profile` 替换成已有配置档 ID 或唯一名称。日程数组建议使用表格编辑：保存的是完整数组，随意缩短数组会被长度校验拒绝。

## 保存失败、冲突与重新读取

| 现象                             | 处理方法                                             |
| -------------------------------- | ---------------------------------------------------- |
| 数字超范围、条目不合法           | 保留当前草稿，修正后再次保存                         |
| 取消提交确认                     | 修改尚未提交，可继续编辑或退出放弃草稿               |
| 确认期间同一字段被其他客户端修改 | 冲突检查拒绝覆盖；重新读取当前值，再决定如何修改     |
| 后端目录不可用或字段缺失         | 检查连接和后端版本；实际可编辑项以重新读取的配置为准 |
| 推送凭据显示为隐藏占位符         | 输入真实新值才能修改；隐藏占位符不能保存回去         |

需要重新读取时，先记下希望保留的修改，Esc 退出编辑器，再输入 `/config` 重新进入。`/reload` 或 Ctrl+R 会重建整个工作台并清除未保存草稿，连接后回到总览；后台任务继续运行。

配置保存成功后，再到[任务与调度](./scheduler)选择单次测试或日常运行。保存成功只说明后端接受配置，不等于游戏任务已经完成。
