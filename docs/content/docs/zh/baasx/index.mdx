**BAASX** 是 BAAS 的独立终端工作台。启动后用键盘或鼠标管理配置档、任务、日常调度、设备和日志；也可以用单次命令把它接入自己的脚本。程序命令写作 `baasx`，包名为 `@baas/baasx`。

它与 Tauri 客户端独立运行，连接同一套服务协议。连接到相同后端时，操作的是后端中的真实配置档；BAASX 的连接偏好、语言和本地环境设置则单独保存。

## 十分钟完成第一次运行

### 1. 启动 BAASX

安装方法和不同平台的解压方式见[安装页](./installation)。在系统终端输入：

```sh
baasx --lang zh
```

如果没有加入 PATH，在解压目录中使用 `./baasx`；Windows PowerShell 使用 `.\baasx.exe`。本文后续统一使用 `baasx`。

想先练习真实终端界面：

```sh
baasx --demo --lang zh
```

`--demo` 不安装运行环境、不连接真实设备；数据只在本次进程中保留。退出后，去掉 `--demo` 再连接自己的服务。

### 2. 连接本地或已有后端

首次启动选择语言和运行方式。本地安装会引导准备私有 Python、服务版后端和 OCR；有已有服务则填写地址，并按隐藏输入框提示输入登录 Key。

页头出现“已连接”后进入总览。安装下载进度、连接成功与游戏任务完成是三种不同状态：连接正常后仍需选配置档、配置设备并检查任务结果。

### 3. 选择或新建配置档

在工作台底部输入：

```text
/profiles
```

选择后按 Enter。新用户可用 `/new-profile`，按提示填写名称并选择区服。`/use <配置档ID或唯一名称>` 可以直接切换。页头会显示当前配置档，执行任务前先核对这里。

进入 `/config` 时如果没有选择配置档，BAASX 会先打开选择器；选好后自动返回配置页。

### 4. 配置设备与任务行为

输入 `/devices` 检查 ADB 设备；在 `/config` 中设置区服对应的设备连接、脚本方式和任务参数。通用设备准备见[模拟器与设备](../features/emulator)。

第一次可以只配置少量明确的任务。配置编辑需要保存并确认，离开未保存的编辑器不会自动写入后端。具体字段操作见[配置编辑](./configuration)。

### 5. 先运行一个任务

输入 `/tasks`，选择一个适合当前账号的任务，阅读确认内容后按 Enter。也可从列表中取得真实任务 ID，再输入 `/run <任务ID>`。不要把页面上的翻译名称当作任务 ID。

运行后看日志与最终状态。窄窗口使用 `/logs`；宽窗口可同时显示工作区和日志，并拖动中间分界线调整比例。

### 6. 再开启日常调度

进入 `/scheduler`，确认哪些任务已启用、优先级和下次执行时间，然后输入：

```text
/start
```

**`/start` 会立即启动当前配置档的调度，不再弹确认。** 要停止时使用 `/stop` 并确认。一次性推图和活动剧情使用 `/oneoff`，不加入日常调度。

## 两种终端用法要分清

| 场景       | 在哪里输入                       | 示例                                              |
| ---------- | -------------------------------- | ------------------------------------------------- |
| 交互工作台 | BAASX 底部输入栏                 | `/config`、`/start`、`/reload`                    |
| 单次 CLI   | PowerShell、Bash、zsh 等系统终端 | `baasx --json status`、`baasx --yes run <任务ID>` |

工作台命令以 `/` 开头。单次 CLI 先写程序名 `baasx`，通常不带 `/`。两种入口不是完全一一对应：例如 `/reload` 重载整个工作台，`baasx reload` 仅在当前命令进程重新读取指令包，详见[命令参考](./cli)。
