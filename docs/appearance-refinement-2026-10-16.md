# 界面细化与主页恢复验收（2026-10-16）

## 主页卡住的原因与修复

本地 `baas-dev` 的共享内存源码仍完整。预览后端在远端更新后发生版本混搭：旧的 `main.service.py` 不接受 `--shm-name`，残留目录联接中的 service 又依赖更新后 deploy 中缺失的函数，导致进不去主页。

预览已恢复为当前本地后端的独立快照，配置保留，预览的远端更新关闭。502 个运行文件均有哈希清单；修复后两次完整重启都进入主页，共享内存 READY 正常，运行初始化分别为 444.1ms / 478.0ms。后续 UI 调试期间再次核验，运行文件没有被覆盖。

启动前增加后端共享内存能力检查：如果入口、适配器或应用接线被旧版本覆盖，直接报告明确的启动错误。详见 [启动排查记录](startup-repair-2026-10-16.md)。
