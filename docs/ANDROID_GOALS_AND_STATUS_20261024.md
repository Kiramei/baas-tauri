## 二、本分支保存的改动

- 前端与传输：配置命令和二进制 ZIP 的回调匹配、整帧发送及失败收尾，配置页签交互，共享日志标题去计数，更新与手操操作的互斥边界。
- 原生 Android：原生横屏画面、主题与浮动菜单、坐标映射、生命周期和有界 worker；保留目标显示器、租约、代次及焦点校验，不向主屏盲注入。
- 手操/脚本共存：`verifyAndroidManualControlOwnership` 不再通过停止调度进入手操。`ManualInputGate` 采用**自动化优先的整手势仲裁**：自动操作前取消当前手操流，自动操作期间丢弃竞争手操流直至 UP/CANCEL；失败必须拒绝，不能伪造输入成功。
- Python Android 适配：配置文件变化检测、主页资源保守 OCR 与刷新、严格库存已满识别及明确的 `SKIPPED/unclaimed` 结果、新增初始化 loading 识别。均保留范围与置信度校验。
- Rust / 日志：移动端命令转发及权限契约、更新查询的单飞与期限、日志批量后台写入及相关测试。

这些是当前源码快照，并不表示每项已随最后安装包验收。用户输入与自动化共用一个游戏状态：不暂停脚本也不代表任意手操都不会改变任务执行结果；自动化优先还意味着手势可能被取消或忽略。

## 三、截图、预览与控制链路

- 预览：Shizuku 用户服务管理独立游戏 VirtualDisplay，经原生 capture / GPU 渲染送到 Android 原生预览组件或横屏组件；不是把编码视频流送给 WebView 解码。
- 脚本截图：从同一 owned display 按需取帧，当前链路仍包含 PNG、Base64、本地 RPC 与 Python 解码，尚未实现零拷贝或二进制优化。
- 控制：Python `android_local` 经本地 RPC、特权 Binder 服务与定向输入到 owned display；手操从原生 View 经租约和相同显示器边界进入。普通自动化链路不依赖 Accessibility 或第三方 adbutils/uiautomator2 控制。
- 焦点恢复有独立安全握手；无法证明 shield 是正确目标窗口时必须拒绝，不用放宽校验或触碰其他应用来掩盖黑屏。

## 六、后续顺序与不变量

1. 在安全拒绝发生的瞬间记录去敏窗口诊断，查明 shield 缺失 / 焦点未恢复的因果；保留 fail-closed 边界。
2. 在同一可复现环境对照旧、新包，先恢复可见游戏及稳定截图，再验整套手操/脚本共存：长按、多指、自动化抢占、迟到 CANCEL、返回、关闭、旧会话失效和错误传播。
3. 在真正冷启动阶段验证初始化 guard，区分游戏加载与识别等待，比较首个主页、误点击及截图新鲜度。
4. 关联 WebView event-loop gap、原生 worker / Binder 和截图耗时，定位真实卡顿后再优化。CPU 每帧全量读回、PNG/Base64 临界区和重复 Binder 诊断目前只是候选，不是已实现收益。
5. 最新包通过后再做物理 ARM / 目标 Android 的构建安装、长时运行与回归；不直接合并为已完成修复。

继续测试仍须遵守：仅获授权免费日常；禁止充值、抽卡及付费资源消耗；不改其他应用声音，不重启共享 Shizuku，不放宽主屏输入边界。任何新验证需后续明确指令。

## 七、独立旧版兼容实验

`codex/android-legacy-shizuku` 仍是另一个本地工作树中的实验，基于旧 `326760f`，其未提交源码**没有混入本分支，也没有随本次推送上传**。

- Shizuku 可运行的最低系统、无线启动门槛与 BAAS 原生后台能力是三件事；Shizuku server v13 不等于 Android 13。
- 实验包含启动前能力检查、旧 Shizuku 构造器门槛、Android 10/11 stack API 与 Android 12+ root-task API 区分；报告 42 项本地测试及 14 个 Kotlin 源文件独立编译通过，非完整 APK 或旧系统实测。
- Android 10+ 的独立 root provider 是最接近原生 VD 数据面的替代设计，尚未接入；Android 8.1/9 input forwarder 还受焦点和生命周期约束，尚未实现。
- 前台游戏 + 后台调度 + 浮钮可以合理降级，但不保留内嵌后台 VD 和同组件回嵌体验，不能称为等效。

合入实验前必须先承接本次安全改动并审查冲突，不能拿旧基线实验包替换当前包。
