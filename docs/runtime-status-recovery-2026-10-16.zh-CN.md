# 后端重启后的运行状态恢复

日期：2026-10-16，时间为北京时间。

## 现场与原因

国际服配置一直显示“停止”，反复点击后没有变化。客户端日志显示，国际服启动成功之后，后端于 22:41:12 重启；后续停止请求均返回 `unknown-config`。独立读取 `/health` 时，后端只有 B 服运行会话，没有国际服会话。RustRover 当时已连接调试器，但没有暂停在断点。

这次是前端残留运行状态：连接恢复没有清除旧 `statusStore`，新后端发送空 `status: {}` 时又落入错误的包装状态分支，产生 `undefined` 键，旧国际服的 `running: true` 因而留下。停止请求已收到回复，但旧后端不会为不存在的会话另外推送停止状态，界面一直显示“停止”。这不是国际服专属的暂停逻辑，也没有证据指向共享内存；本次现场使用 WebSocket。

## 修复

- 连接代际失效及 provider 重建时清除旧运行状态，由新后端重建；保留配置和已有日志。
- 空状态快照正确清空会话，拒绝无效包装状态；正常逐配置、逐字段更新继续合并。
- 停止收到 `unknown-config` 后校正对应旧状态。请求发送时捕获状态对象身份，只有该状态未被新 provider 更新替换时才能清理，防止跨通道延迟回执误删新任务。
- 不改变后端接口，兼容现有后端；没有修改国际服任务、游戏配置或用户正在编辑的主页样式。

## 验证与范围

- 真实调试客户端已显示“国际服”“服务已连接”“启动”“暂无正在执行的任务”。
- `bun test tests/frontend`：64 通过、0 失败，768 次断言。
- `bunx tsc --noEmit` 和 `git diff --check` 通过。
- 新回归使用真实状态仓库与模拟通道，覆盖重连空快照、旧代际消息、增量更新、其他配置保留、旧停止回执晚到、无外部回调及错误回执。

本次没有重新启动国际服玩法，验证的是本次实际故障的状态恢复与回执处理；不将其表述为国际服全部任务或所有阻塞调用均已实测可停止。
